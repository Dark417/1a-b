# 14 · Data Engineering for AI

> Skill #14 (Tier 2 — Important). *Ingestion, cleaning, chunking, labeling, and
> pipelines at scale.* ~50% — "garbage in" is the most common real-world failure.
> See the rationale in
> [`../11.agent-ai-engineer/03.ranked-skills.md`](../11.agent-ai-engineer/03.ranked-skills.md).

---

## 1. What it is

Building the **data pipelines** that feed AI systems: ingest, clean, transform,
**chunk**, deduplicate, and **label** data at scale; batch *and* streaming
pipelines; dataset curation for pretraining / fine-tuning / RAG; and feature/
data stores.

It exists because **data quality dominates model quality.** The most common
real-world failure isn't the model — it's "garbage in": dirty, duplicated,
mislabeled, or badly chunked data. The pipeline is where AI systems quietly
succeed or fail.

## 2. Why employers want it

R1 lists data engineering for AI in the top 10; it's the unglamorous skill that
decides outcomes (S7, S8, S15, S27, R1, R11). The signal:

- **You make data trustworthy** — clean, deduplicated, validated, and fresh — so
  models and RAG actually work.
- **You build pipelines that scale and don't silently break** — with validation,
  monitoring, and reproducibility.
- **You curate datasets** for fine-tuning and RAG, the single biggest lever on
  quality (skill [`12`](12.fine-tuning-model-adaptation.md)/[`05`](05.retrieval-augmented-generation.md)).

## 3. Mental model

A data pipeline is **ingest → clean → transform → load**, instrumented and
versioned, in batch or streaming.

```
sources ─► ingest ─► validate ─► clean/normalize ─► dedup ─► transform
(APIs,                                                           │
 files,                                          (chunk | label | embed | feature)
 DBs,                                                            │
 streams)                                          ─► store (warehouse / lake / vector DB)
                          (quality checks + monitoring + lineage throughout)
```

**For AI specifically, four transforms matter most:**

1. **Cleaning/normalization** — strip boilerplate/HTML, fix encoding, normalize
   whitespace/unicode, handle PII (skill [`19`](19.safety-alignment-guardrails.md)),
   remove low-quality content.
2. **Deduplication** — exact + **near-duplicate** (MinHash/LSH, embedding
   similarity). Critical: duplicates inflate eval scores, waste training, and bias
   models.
3. **Chunking** (for RAG) — split documents into retrieval units with the right
   size/overlap/boundaries (skill [`05`](05.retrieval-augmented-generation.md)).
4. **Labeling/curation** — for fine-tuning: format into clean instruction/chat
   pairs, filter noise, balance, and hold out an eval set. Quality > quantity.

**Batch vs streaming.** Batch (scheduled, large volumes — most training/RAG
indexing) vs streaming (continuous, low-latency — real-time features, live index
updates). Many systems are **hybrid** (batch backfill + streaming increments).

**Cross-cutting:** **data validation** (schema, ranges, nulls — fail loudly),
**lineage/versioning** (reproduce any dataset), **monitoring** (volume, freshness,
quality drift), and **idempotency** (re-runnable without double-counting).

## 4. The landscape

**Ingestion & parsing.** API/DB/file connectors · document parsing for unstructured
data (unstructured.io, PyMuPDF, Docling, Tika, LlamaParse) · web scraping · CDC
for databases.

**Processing engines.** pandas/Polars (single-node) · **Spark** / Dask / Ray (big
data) · DuckDB (fast local analytics) · streaming: **Kafka**, Flink, Spark
Streaming.

**Orchestration.** **Airflow** (mature, batch DAGs) · **Dagster** (asset/data-
aware) · **Prefect** (Pythonic) · dbt (SQL transforms in the warehouse).

**Storage.** Warehouses (Snowflake, BigQuery, Redshift) · lakes/lakehouse (S3/GCS
+ Delta/Iceberg/Hudi) · vector DBs (skill [`09`](09.vector-databases-embeddings.md)) ·
feature stores (Feast, Tecton).

**Quality & validation.** Great Expectations, Pandera, dbt tests, Soda · drift
(Evidently) · lineage (OpenLineage, Marquez).

**Labeling.** Label Studio, Prodigy, Argilla (LLM-data-centric) · weak supervision
(Snorkel) · LLM-assisted labeling (use a strong model to label/clean, then human-
verify a sample).

**AI-specific dataset curation.** Dedup (datasketch/MinHash, semantic), quality
filtering (heuristics + classifier + LLM judge), decontamination (remove
eval-set overlap), PII scrubbing, and formatting to the model's chat template.

## 5. Worked example

A reproducible **RAG ingestion pipeline step**: parse → clean → **dedup** →
chunk → ready-to-embed records, with a validation gate. Pure-Python and runnable
(the pattern scales to Spark/Dagster).

```python
"""ingest_pipeline.py — clean -> dedup -> chunk -> validate. CPU, exit 0."""
import re
import hashlib

raw_docs = [
    {"id": "a", "text": "  Acme refund policy:\n\nReturns within 30 days.  "},
    {"id": "b", "text": "Acme refund policy: Returns within 30 days."},   # near-dup of a
    {"id": "c", "text": "API rate limit is 1000 req/min on Pro. " * 20},  # long -> chunked
]

def clean(text: str) -> str:
    text = re.sub(r"\s+", " ", text).strip()        # normalize whitespace
    return text

def shingle_hash(text: str) -> str:
    norm = re.sub(r"[^a-z0-9 ]", "", text.lower())  # normalize for dedup
    return hashlib.md5(norm.encode()).hexdigest()    # exact-after-normalize dedup key

def chunk(text: str, size: int = 120, overlap: int = 20):
    out, i = [], 0
    while i < len(text):
        out.append(text[i:i + size])
        i += size - overlap                          # sliding window with overlap
    return out

seen, records = set(), []
for doc in raw_docs:
    text = clean(doc["text"])
    key = shingle_hash(text)
    if key in seen:                                  # drop near-duplicates
        continue
    seen.add(key)
    for j, ch in enumerate(chunk(text)):
        records.append({"doc_id": doc["id"], "chunk_id": j, "text": ch})

# Validation gate: fail loudly if the pipeline produced bad data.
assert records, "pipeline produced no records"
assert all(r["text"].strip() for r in records), "empty chunk produced"
assert len({r["doc_id"] for r in records}) == 2, "dedup failed (expected 2 docs)"

print(f"{len(records)} chunks from {len({r['doc_id'] for r in records})} unique docs")
for r in records[:3]:
    print(f"  {r['doc_id']}#{r['chunk_id']}: {r['text'][:50]!r}")
# Next stage: embed `records` -> upsert to the vector store (skill #09).
```

The load-bearing ideas: **normalize then dedup** (doc `b` is dropped as a
near-duplicate of `a`), **chunk with overlap**, and a **validation gate** that
fails loudly on bad output. In production you'd run this in Dagster/Airflow with
schema validation (Great Expectations), lineage, incremental processing, and a
distributed engine (Spark/Ray) for scale — but the discipline is the same.

## 6. How to learn it

**Beginner (0–3 months).** Build a batch pipeline with pandas/Polars: ingest,
clean, dedup, save; parse PDFs to text. *Milestone:* a reproducible script that
turns messy sources into clean records.

**Intermediate / job-ready (3–9 months).** Orchestrate with Airflow/Dagster; add
data validation (Great Expectations); build a RAG ingestion pipeline with
chunking + embedding; curate a fine-tune dataset with dedup + quality filtering.
*Milestone:* an orchestrated, validated pipeline feeding a vector store or a
fine-tune.

**Expert (9+ months).** Scale with Spark/Ray; streaming pipelines (Kafka/Flink);
lineage + monitoring + freshness SLAs; large-scale dedup/decontamination/quality
classifiers for pretraining-scale data. *Milestone:* you own a production data
platform feeding models and RAG, with quality guarantees.

## 7. Interview signals

- **"Your RAG quality is poor — could it be the data?"** Yes, usually: bad
  chunking, duplicates, dirty text, stale index, parsing errors. Strong answer
  audits the *pipeline* before blaming the model.
- **"How do you deduplicate at scale?"** Exact (hashing) + near-dup (MinHash/LSH
  or embedding similarity); why it matters (eval inflation, bias, waste).
- **"How do you curate a fine-tuning dataset?"** Clean → dedup → quality filter
  (heuristics + classifier/LLM judge) → decontaminate (remove eval overlap) →
  format to chat template → hold out an eval set; quality > quantity.
- **"Batch vs streaming for your index?"** Batch for backfill/large reindex,
  streaming for freshness; many systems do hybrid. Name the freshness/cost
  tradeoff.
- **"How do you stop a pipeline from silently corrupting data?"** Schema/range
  validation that fails loudly, lineage, monitoring (volume/freshness/quality),
  idempotency, and alerts.
