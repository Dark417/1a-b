# 01 · Encoder-only models — the BERT family

> **Intuition.** A *decoder* LLM reads left-to-right and predicts the next token.
> But for *understanding* a sentence — classifying its sentiment, tagging its
> entities, embedding it for search — you want every token to see the whole
> sentence, both left and right. That is what an **encoder-only** model does:
> stack bidirectional self-attention, and train it to fill in blanks. The output
> is not text but a *contextual vector per token* you attach a small head to.

These models dominated 2018–2020 NLP and are still the workhorses of embeddings,
retrieval, reranking, and classification.

---

## 1. BERT — the template

**Architecture (in words).** A Transformer *encoder* stack (Vaswani et al. 2017,
no causal mask, no decoder): token embeddings + learned absolute position
embeddings + a *segment* embedding (A/B), then `L` layers of
{multi-head self-attention → residual+LayerNorm → FFN(GELU) → residual+LayerNorm}.
BERT-base = 12 layers, 768 hidden, 12 heads, 110M params; BERT-large = 24/1024/16,
340M. Vocabulary = 30k **WordPiece**. Max sequence 512. Special tokens
`[CLS]` (sequence-level representation), `[SEP]` (separator).

**Pretraining objectives.**

1. **Masked Language Modeling (MLM).** Mask 15% of tokens; predict them from
   bidirectional context. Of the masked positions, 80% → `[MASK]`, 10% → random
   token, 10% → unchanged (so the model can't assume a `[MASK]` is always there).
   Loss is cross-entropy over the vocabulary at masked positions only:

   $$\mathcal{L}_{\text{MLM}} = -\sum_{i \in M} \log p(x_i \mid x_{\setminus M})$$

2. **Next-Sentence Prediction (NSP).** Given a sentence pair (A, B), predict
   whether B actually follows A (binary). Later shown to be largely unhelpful.

**What was novel.** *Deep bidirectionality* via the masking trick — earlier
models (ELMo, GPT-1) were left-to-right or shallow concatenations. BERT set SOTA
across GLUE/SQuAD by fine-tuning a single architecture.

**Strengths / limits.** Best-in-class for understanding tasks and embeddings;
**cannot generate** fluent text (not autoregressive). The artificial `[MASK]`
token creates a pretrain/finetune mismatch (it never appears at finetune time).
Quadratic attention caps it at 512 tokens.

## 2. The variants — what each one changed

### RoBERTa (Robustly optimized BERT) — Meta, 2019
Same architecture, *better recipe*: **remove NSP**, train ~10× longer on ~10×
more data (160GB), use **dynamic masking** (re-mask each epoch instead of once),
bigger batches, byte-level BPE (50k vocab). Conclusion: BERT was *undertrained*.
RoBERTa is "just BERT, done right" and beats it everywhere.

### ALBERT (A Lite BERT) — Google, 2019
Two parameter-reduction tricks so you can train much larger hidden sizes:
- **Factorized embedding parameterization.** Decouple vocab embedding size $E$
  from hidden size $H$: project $V\times E$ then $E\times H$ instead of $V\times H$.
- **Cross-layer parameter sharing.** All layers share the same weights → 18× fewer
  params (ALBERT-base = 12M vs BERT-base 110M).
- **Sentence-Order Prediction (SOP)** replaces NSP (predict if two consecutive
  segments are swapped — a harder, more useful task).
Smaller in params but *not* faster at inference (same compute per layer).

### DistilBERT — Hugging Face, 2019
**Knowledge distillation**: train a 6-layer student to match a 12-layer BERT
teacher. The loss combines (a) the student's MLM loss, (b) a **distillation
loss** (KL to the teacher's softened logits, temperature $T$), and (c) a cosine
embedding loss aligning hidden states:

$$\mathcal{L} = \alpha\,\mathcal{L}_{\text{MLM}} + \beta\,T^2\,\text{KL}\!\big(\sigma(z_s/T)\,\|\,\sigma(z_t/T)\big) + \gamma\,\mathcal{L}_{\cos}$$

Result: 40% fewer params, 60% faster, ~97% of BERT's GLUE score. The blueprint
for shipping encoders on edge/CPU.

### ELECTRA — Google, 2020
Replaces MLM with **Replaced-Token Detection (RTD)**. A small generator (a tiny
MLM) corrupts some tokens; the main model (discriminator) classifies *every*
token as original-or-replaced. Because the loss comes from **all** positions
(not just the 15% masked), ELECTRA is far more **sample-efficient** — a small
ELECTRA matches a much larger BERT for the same compute. No `[MASK]` at use time
either, fixing the pretrain/finetune mismatch.

### DeBERTa — Microsoft, 2020 (v3 2021)
Two ideas:
- **Disentangled attention.** Each token is represented by *two* vectors —
  content and relative-position — and attention scores sum content-content,
  content-position and position-content terms (position-position is dropped). The
  relative-position term generalizes better than BERT's absolute embeddings.
- **Enhanced Mask Decoder.** Inject absolute positions late, just before the
  softmax output, to disambiguate (e.g. subject vs object).
- **DeBERTa-v3** swaps MLM for **ELECTRA-style RTD** + gradient-disentangled
  embedding sharing — long the top of GLUE/SuperGLUE for its size.

## 3. Mechanisms & component links

Encoders predate the modern efficiency stack, but the building blocks recur:

- **Attention** — the bidirectional self-attention here is the same scaled
  dot-product attention; modern decoders add causal masking and KV caching
  (`08.kv_cache.py`) which encoders don't need (no autoregression).
- **Normalization** — BERT uses **post-LayerNorm**; modern models prefer
  **pre-norm RMSNorm** (`06.rmsnorm.py`) for training stability.
- **Position** — BERT uses *learned absolute* positions; the field moved to
  relative/rotary schemes (`01.rope.py`, `02.alibi.py`), which DeBERTa's
  disentangled attention anticipates.

## 4. When to use which

| Need | Pick |
|---|---|
| Sentence/document embeddings, retrieval | RoBERTa / DeBERTa-v3 (or sentence-transformers built on them) |
| Cheap CPU classification | DistilBERT |
| Best accuracy per FLOP at pretrain | ELECTRA / DeBERTa-v3 |
| Multilingual understanding | XLM-R (RoBERTa multilingual) / mBERT |
| **Text generation** | none of these — use a decoder (`03.gpt-line.md`) |
