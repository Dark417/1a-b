# 03 · Ranked AI-Engineer Skills (the centerpiece)

The ranked, numbered list of skills/knowledge areas an **AI engineer** is hired
for, most → least demanded, derived from the corpus in
[`02.job-descriptions.md`](02.job-descriptions.md) and the method in
[`01.research-method.md`](01.research-method.md). Frequencies are the **weighted
demand score** translated to an approximate "share of sources that asked for it"
(see [`04.skill-frequency.md`](04.skill-frequency.md) for the table).

Skills are grouped into three tiers. **The number is the canonical rank** and is
stable — it seeds one explainer file per skill in
[section 12](../12.agent-ai-skills/). The clean machine-readable list lives in
[`agent-ai-engineer.skill.md`](agent-ai-engineer.skill.md).

> Reading guide: *Core* = table stakes, absence is disqualifying. *Important* =
> strong demand, expected for most applied roles. *Differentiating* = raises you
> above the bar or gates a specialist role.

---

## TIER 1 — Core (table stakes) · ranks 01–10

### 01. Python & software-engineering craft — *~95% of sources*
The single most universal requirement. Every archetype — research engineer, FDE,
LLM engineer, applied scientist — leads with *strong software engineer first*.
Means: idiomatic Python, clean/tested/documented code, debugging across the
stack, version control, packaging, async/concurrency. Employers want it because
AI systems are *software* — most failures are engineering failures (a flaky
pipeline, an unhandled timeout), not modeling failures. A model is a function
call; the job is the system around it. *(S1, S3, S4, S6, S8, S15, S17, S21, R1, R9.)*

### 02. ML & deep-learning foundations — *~85%*
Linear algebra/probability intuition, gradient descent, over/under-fitting,
regularization, the bias–variance picture, and the DL toolbox (CNNs, RNNs,
attention, embeddings, loss functions, optimizers). R1 puts deep learning in
28.1% of postings as a named skill — and it's *implied* almost everywhere else.
Employers want it so you can reason about *why* a model behaves as it does,
choose the right approach, and not treat the model as a black box. Even
"prompt-only" applied roles need this to debug quality. *(S6, S7, S8, S13, S15, S17, R1, R2.)*

### 03. LLM & transformer architecture knowledge — *~85%*
Understand the transformer end to end: self-attention, multi-head/GQA/MQA,
positional encodings (RoPE/ALiBi), the FFN, tokenization, context windows,
KV-cache, sampling/decoding, and scaling laws. Know the model landscape (GPT,
Claude, Llama, Mistral, Qwen, DeepSeek) and their tradeoffs. Employers want it
because every downstream decision — context budget, latency, cost, fine-tune vs
prompt, which model — flows from understanding how transformers actually work.
*(S7, S9, S10, S12, S17, R1, R6.)* → repo: [`05.transformers/`](../05.transformers/).

### 04. LLM API integration & prompt engineering — *~80%*
Fluency with hosted-model APIs (OpenAI, Anthropic, Gemini): sync + streaming,
token counting, context windows, system prompts, function/tool calling,
structured output, multi-turn state. Plus prompt *engineering* as a discipline —
designing, measuring, and **optimizing** prompts (not vibes). R1 reports
prompt-engineering openings up 135.8% YoY. Employers want it because it's the
fastest path from idea to working product and the daily surface of most applied
AI work. *(S2, S3, S4, S11, S12, S21, S22, S23, R1.)* → [`07.frameworks/prompt-engineering/`](../07.frameworks/prompt-engineering/).

### 05. Retrieval-Augmented Generation (RAG) — *~75%*
The most-requested *application pattern* in production. End to end: chunking,
embeddings, indexing, retrieval (dense/sparse/hybrid), reranking, context
assembly, citation, and the failure modes (lost-in-the-middle, stale index, bad
chunking). Employers want it because it grounds LLMs in their proprietary data
without retraining — the default way enterprises get value, and the skill most
likely to land an applied job. *(S2, S3, S4, S17, S19, S20, S21, S22, S24, S25, S26, S30, R1.)*
→ [`07.frameworks/rag/`](../07.frameworks/rag/).

### 06. Agent design & orchestration — *~70% and rising fastest*
Build agent loops: tool/function calling, planning/reasoning, sub-agent
orchestration, memory/context management, multi-agent topologies (supervisor,
swarm, pipeline) with LangGraph/CrewAI/AutoGen/OpenAI-Agents/Anthropic-SDK, and
protocols like **MCP**. R1/R2 call agentic the highest-opportunity, lowest-supply
category of 2026. Employers want it because agents are how LLMs move from
chat to *doing work*, and the talent pool is thin. *(S2, S4, S10, S11, S12, S29, S30, R1, R2.)*
→ [`07.frameworks/agents/`](../07.frameworks/agents/), [`08.claudecode/`](../08.claudecode/).

### 07. Evaluation & LLM testing — *~65% and rising*
Designing eval suites for non-deterministic systems: task metrics, LLM-as-judge,
RAG metrics (faithfulness, context precision/recall via Ragas/DeepEval),
agent-trajectory evals, regression/CI gating, human eval. Now its own role at
Scale (`S16`) and a named requirement at Anthropic (`S3`, `S5`). Employers want it
because you can't ship or improve what you can't measure — and LLM quality is
slippery, so disciplined evaluation is the difference between a demo and a
product. *(S3, S5, S16, S21, S22, S29, S30, R8.)* → [`07.frameworks/evaluation/`](../07.frameworks/evaluation/).

### 08. PyTorch (and the DL framework stack) — *~65%*
The dominant framework: R1 reports PyTorch in **37.7%** of postings (TensorFlow
32.9%, JAX in research/perf roles). Build/train/fine-tune models, custom modules,
data loaders, mixed precision, `torch.compile`. Employers want it because it's
the lingua franca of model work — Mistral live-codes core DL components in it
(`S17`), Meta/NVIDIA require it (`S7`, `S9`). For pure prompt-API roles it's
lighter, hence Tier-1-low rather than top. *(S7, S9, S15, S17, R1.)* → [`02.dl/`](../02.dl/), [`09.huggingface/`](../09.huggingface/).

### 09. Vector databases & embeddings — *~60%*
Embeddings (sentence-transformers, BGE, OpenAI/Cohere), similarity search, and
vector stores (FAISS, Chroma, Qdrant, Milvus, Weaviate, pgvector, Pinecone):
indexing, ANN tradeoffs (HNSW/IVF), metadata filtering, hybrid search. Employers
want it because it's the storage/retrieval backbone of RAG and agent memory — you
can't build #05 or #06 well without it. *(S17, S21, S22, S24, S26, S30, R1.)*
→ [`07.frameworks/vector-databases/`](../07.frameworks/vector-databases/), [`07.frameworks/embeddings/`](../07.frameworks/embeddings/).

### 10. Cloud platforms & deployment — *~60%*
Ship on AWS/GCP/Azure: containers, serverless, managed ML (SageMaker/Vertex/
AML), IaC (Terraform), CI/CD, secrets, scaling, cost control. Employers want it
because a model that only runs on your laptop has no value — productionizing is
the job, and cloud is where it runs. *(S1, S11, S13, S15, S25, R1, R2.)*

## TIER 2 — Important (strong demand) · ranks 11–22

### 11. MLOps / LLMOps — *~55%*
The operational discipline: experiment tracking, model/prompt versioning,
registries, CI/CD for models, serving, monitoring/observability, drift, rollback,
**cost & latency control**, guardrails. Employers want it because LLM systems are
live products that degrade silently; ops is what keeps them reliable and
affordable. *(S14, S15, R1, R2, R11.)* → [`07.frameworks/observability/`](../07.frameworks/observability/).

### 12. Fine-tuning & model adaptation — *~50%*
Adapt models to a domain: full FT, **PEFT (LoRA/QLoRA)**, instruction tuning,
SFT, data curation, and knowing *when not to* (often RAG/prompting wins). R1
calls LLM fine-tuning "the most sought-after specialized skill in enterprise AI."
Employers want it to squeeze quality/latency/cost beyond what prompting gives,
and to build differentiated models on proprietary data. *(S7, S12, S17, R1, R6.)*
→ [`07.frameworks/fine-tuning/`](../07.frameworks/fine-tuning/), [`06.training-techniques/`](../06.training-techniques/).

### 13. System design for AI products — *~50%, weighted up by seniority*
Architect end-to-end LLM systems: data flow, retrieval + model + tool + cache
layers, latency/cost/quality tradeoffs, fallbacks, rate limiting, multi-tenant
concerns, evaluation in the loop. Employers want it because senior/staff hires
own *systems*, not snippets; this is the skill that separates a senior from a
junior. *(S1, S2, S8, S11, S19, S20, R9.)* *(Inferred-expected at senior level
even where JDs are terse — flagged per S14/S18.)*

### 14. Data engineering & pipelines for AI — *~50%*
Ingest, clean, transform, chunk, and label data at scale; build pipelines
(batch + streaming), feature stores, and dataset curation for pretraining/
fine-tuning/RAG. R1 lists data engineering for AI in the top 10. Employers want
it because data quality dominates model quality — "garbage in" is the most common
real-world failure. *(S7, S8, S15, S27, R1, R11.)* → [`07.frameworks/data-processing/`](../07.frameworks/data-processing/).

### 15. Communication & stakeholder translation — *~50%, weighted up by seniority/FDE*
Explain technical results to non-experts and leadership; translate fuzzy customer
needs into architecture and a plan; write clearly. Explicitly required at
DeepMind (`S6`), Anthropic (`S3`), and every FDE role (`S2`, `S4`, `S19`, `S20`).
Employers want it because AI work is cross-functional and ambiguous; the
bottleneck is often alignment, not code. *(S3, S4, S6, S15, S19, S20, R12.)*

### 16. Inference optimization & model serving — *~45%*
Make models fast and cheap to run: KV-cache, paged attention, continuous
batching, quantization (GPTQ/AWQ/GGUF), speculative decoding, and serving engines
(vLLM, TGI, SGLang, TensorRT-LLM, Triton, Ollama). Employers want it because
inference is the dominant production cost and latency driver; required for
serving-team roles, valued everywhere. *(S9, S10, S18, S28, R1.)*
→ [`07.frameworks/serving-inference/`](../07.frameworks/serving-inference/), [`10.gpu/08.inference-optimization.md`](../10.gpu/).

### 17. Product sense & shipping — *~45%, strong at startups/FDE*
Judgment about *what* to build: scoping an MVP, prioritizing by user value,
iterating from real usage, pragmatic tradeoffs, and actually shipping. Startups
and FDE roles hire on demonstrated shipped work (repos, deployed agents). 
Employers want it because AI capability is cheap; turning it into a product users
keep is the scarce skill. *(S2, S4, S19, S20, S21, S22, R10.)*

### 18. NLP foundations — *~40%*
Tokenization, embeddings, classification/NER/QA/summarization, sequence
labeling, evaluation metrics (BLEU/ROUGE/F1), and the pre-LLM toolkit that still
underpins LLM work. R1 reports NLP in 19.7% of postings as a named skill (higher
implicitly). Employers want it because LLMs are NLP systems; the fundamentals
explain tokenization quirks, multilinguality, and eval design. *(S7, S12, S17, R1.)*
→ [`04.nlp/`](../04.nlp/).

### 19. Safety, alignment & guardrails — *~40%, defining at labs*
Red-teaming, failure-mode thinking, prompt-injection/jailbreak defense, PII
handling, content filtering, RLHF/DPO concepts, responsible-AI practices, and
guardrail frameworks (Llama Guard, NeMo Guardrails, Guardrails-AI). Central at
Anthropic (`S3`, `S5`), Meta responsible-LLMs (`S7`), and every enterprise
deployment. Employers want it because a system that behaves unsafely or leaks data
is a liability, not a product. *(S3, S5, S7, S29, R10, R12.)* → [`07.frameworks/guardrails/`](../07.frameworks/guardrails/).

### 20. A second programming language — *~40%, seniority signal*
Beyond Python: **Go or C++** (OpenAI `S1`, NVIDIA `S9`), **TypeScript** for agent/
web/FDE work (`S4`, `S29`, `S30`), sometimes Scala (Databricks `S15`), Rust for
perf. Employers want it because production systems span services, edge, and
performance-critical code that Python alone doesn't cover; it signals
range. *(S1, S4, S9, S15, S29, S30.)*

### 21. Containers & Kubernetes — *~35%*
Docker + Kubernetes for packaging and scaling model workloads, GPU scheduling,
and orchestration (Ray, KServe). R1/R2: Kubernetes is the top-named MLOps tool
(~17.6%). Employers want it because it's how AI services run reliably at scale and
how GPUs get shared across teams. *(S11, S15, S27, R1, R2, R11.)* → [`10.gpu/07.multi-gpu.md`](../10.gpu/).

### 22. Observability & monitoring for LLMs — *~35% and rising*
Trace prompts/responses/tool-calls, token & cost dashboards, latency/error SLOs,
quality drift, and tooling (LangSmith, Langfuse, Phoenix/Arize, Helicone,
OpenLLMetry). Its own role at Anthropic (`S5`). Employers want it because LLM
quality and spend drift invisibly; you need eyes on production to catch
regressions and runaway cost. *(S5, S14, R1, R11.)* → [`07.frameworks/observability/`](../07.frameworks/observability/).

## TIER 3 — Differentiating (edge / niche / seniority) · ranks 23–32

### 23. GPU programming & CUDA — *~30%, gates perf roles*
Write/optimize GPU kernels (CUDA C/C++, Triton, cuTile), understand the memory
hierarchy, occupancy, coalescing, profiling (Nsight). Required at NVIDIA (`S9`,
`S10`) and perf/inference teams (`S28`); a strong differentiator elsewhere.
Employers want it because squeezing the hardware is where the biggest latency/cost
wins live. *(S9, S10, S28.)* → [`10.gpu/`](../10.gpu/).

### 24. Distributed training — *~25%, gates infra roles*
Train large models across many GPUs/nodes: data/tensor/pipeline parallelism,
FSDP, DeepSpeed/ZeRO, Megatron, NCCL, and the fabric (InfiniBand/RoCE/NVLink).
Required for distributed-systems roles (`S27`, `S28`), valued at labs. Employers
want it because frontier models can't be trained any other way; it's a scarce,
high-leverage skill. *(S27, S28, S7.)* → [`10.gpu/07.multi-gpu.md`](../10.gpu/), [`06.training-techniques/`](../06.training-techniques/).

### 25. Multimodal AI — *~25% and rising*
Vision-language (CLIP, LLaVA, Qwen-VL, GPT-4V), speech (Whisper), image/video
generation (diffusion), and cross-modal retrieval. Named at Meta (`S7`) and
Microsoft (`S12`). Employers want it because product surfaces are going
multimodal (documents, screenshots, audio) and most LLM engineers are
text-only. *(S7, S12, R3.)* → [`03.generative-models/`](../03.generative-models/).

### 26. Hugging Face ecosystem — *~25%*
Transformers, Datasets, Tokenizers, Accelerate, PEFT, TRL, Diffusers, the Hub,
and Spaces/Gradio: the practical glue for loading, fine-tuning, and sharing open
models. Employers want it because it's the default toolkit for working with
open-weight models — implied wherever fine-tuning/open models appear. *(S12, S17, R6.)*
→ [`09.huggingface/`](../09.huggingface/).

### 27. RLHF / preference optimization — *~20%, lab-weighted*
Reward modeling, PPO, **DPO** and variants, preference-data pipelines, and
RL-for-reasoning (the R1/o1 line). Named at Meta (`S7`), Netflix (`S14`), Scale
(`S16`). Employers want it because it's how raw models become helpful, harmless,
and aligned — core at labs, differentiating elsewhere. *(S7, S14, S16, R1.)*
→ [`06.training-techniques/`](../06.training-techniques/).

### 28. Research literacy & publications — *~20%, research-track*
Read, reproduce, and build on papers; first-author publications (NeurIPS/ICML/
ICLR/ACL) for research roles; track SOTA. Required at Meta/DeepMind research
tracks (`S6`, `S7`); a strong signal at labs even when not required (`R10`).
Employers want it because the field moves monthly; staying current is part of the
job, and research output is credible evidence of ability. *(S6, S7, S12, R10, R12.)*

### 29. Orchestration & workflow frameworks — *~20%*
Beyond single agents: pipeline/flow tools (LangGraph flows, Haystack pipelines,
Flowise/Langflow, Burr, ControlFlow, DSPy) for composing multi-step LLM
applications with branching, retries, and state. Employers want it because real
products are graphs of LLM/tool/retrieval steps, not one call. *(S11, S29, S30.)*
→ [`07.frameworks/orchestration/`](../07.frameworks/orchestration/).

### 30. Domain / industry expertise — *~20%, FDE-weighted*
Depth in a vertical (healthcare, fintech, legal, defense, life sciences) or the
ability to context-switch across them. Valued at Anthropic Applied-AI (`S3`,
life-sciences variant), Palantir/Salesforce FDE (`S19`, `S20`). Employers want it
because the hard part of applied AI is the *domain*, not the model — earns trust
and unlocks real use cases. *(S3, S4, S19, S20.)*

### 31. Classic ML & data science — *~15%*
Tabular ML (gradient boosting, feature engineering), classical statistics,
experiment design, A/B testing, and the scikit-learn world. Still asked at
big-tech ML roles (`S8`, `S13`, `S15`). Employers want it because not every
problem needs an LLM; knowing when a simpler model wins is senior judgment.
*(S8, S13, S15, R7.)* → [`01.ml/`](../01.ml/).

### 32. MCP & emerging agent protocols — *~15% and rising fast*
Model Context Protocol (build servers/clients, expose tools/resources) and
adjacent protocols (A2A, ACP) that standardize how agents access tools and talk
to each other. Named at Anthropic FDE (`S4`), GE Vernova (`S30`), Deloitte (`S29`).
Employers want it because it's becoming the interoperability layer for agentic
systems — early-but-accelerating, a real differentiator now. *(S4, S29, S30.)*
→ [`07.frameworks/mcp/`](../07.frameworks/mcp/), [`08.claudecode/`](../08.claudecode/).

## How to use this list

- **Learners:** Tier 1 is your non-negotiable base; build a project that exercises
  #01–#10 together (a RAG + agent app with evals on cloud). Then pick a Tier-3
  specialty (#23/#24 for infra, #25 for multimodal, #27 for alignment) to stand
  out.
- **Hiring/JD writers:** require Tier 1, list Tier 2 as "strong plus," and pick
  Tier 3 items only if the role genuinely needs them (over-asking shrinks your
  pool).
- **Section 12:** each numbered skill gets a deep explainer at
  [`../12.agent-ai-skills/NN.<skill>.md`](../12.agent-ai-skills/), named per
  [`agent-ai-engineer.skill.md`](agent-ai-engineer.skill.md).
