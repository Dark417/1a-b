> SWE craft.* The single most universal requirement in AI-engineer postings
> (~95% of sources). See the rationale in

## 1. What it is

The ability to write **production-grade software in Python**: clean, idiomatic,
tested, documented, debuggable, packaged, and concurrent code — plus the broader
software-engineering craft (version control, code review, CI, design, error
handling) that surrounds it.

This skill exists because **AI systems are software systems**. A model is a
function call; the job is the durable, observable, correct *system* around that
call — the ingestion pipeline, the retry logic, the streaming server, the config
plumbing, the tests that catch regressions. The overwhelming majority of
production failures are *engineering* failures (a flaky pipeline, an unhandled
timeout, a race in async code, an off-by-one in chunking) rather than modeling
failures.

## 2. Why employers want it

Every AI archetype — research engineer, forward-deployed engineer (FDE), LLM
engineer, applied scientist — leads its job description with *"strong software
engineer first."* The signal employers read:

- **You ship reliable systems, not notebooks.** Code that others can read, run,
  test, and extend.
- **You debug across the stack.** From a CUDA OOM down to a misconfigured env var.
- **You de-risk the team.** Tests, types, and CI mean your changes don't break
  production silently.

Because the model layer is increasingly a commodity API call, the *differentiated*
value is the engineering quality of everything else. This is why a brilliant
prompt-only candidate who can't write a clean async client loses to a solid
engineer who can.

## 3. Mental model

Think in **four concentric rings** of competence:

```
  │   │ 3. CORRECTNESS: tests, types, errors, │   │

  │   │  ┌─────────────────────────────────┐  │   │
  │   │  │ 2. STRUCTURE: modules, classes, │  │   │
  │   │  │    interfaces, data models      │  │   │
  │   │  │  ┌───────────────────────────┐  │  │   │
  │   │  │  │ 1. SYNTAX: idiomatic      │  │  │   │
  │   │  │  │    Python, stdlib fluency │  │  │   │
  │   │  │  └───────────────────────────┘  │  │   │
  │   │  └─────────────────────────────────┘  │   │
  │   └───────────────────────────────────────┘   │
  └─────────────────────────────────────────────┘
```

Core Python concepts an AI engineer must own cold:

- **Data model & duck typing** — dunder methods, iterators/generators,
  context managers, descriptors. Pythonic code leans on protocols, not casts.
- **Concurrency models** — `asyncio` for I/O-bound LLM/API fan-out;
  `concurrent.futures` thread pools for blocking I/O; multiprocessing for
  CPU-bound work (the GIL means threads don't parallelize CPU). Most AI workloads
  are I/O-bound (network round-trips), so **async is the default** for batching
  hundreds of concurrent API calls.
- **Typing** — type hints + `mypy`/`pyright` catch a large class of bugs before
  runtime and make code self-documenting. `pydantic` turns types into runtime
  validation — the backbone of structured LLM output.
- **Error handling** — explicit exceptions, retries with exponential backoff +
  jitter, timeouts, circuit breakers. LLM/API calls *will* fail; resilience is
  table stakes.

## 4. The landscape

| Concern | Tools / techniques | Tradeoffs |
|---|---|---|
| **Packaging / env** | `uv` (fast, modern), `poetry`, `pip`+`venv`, `pip-tools`, `conda` | `uv` is the new fast default; `conda` still wins for non-Python binary deps (CUDA, MKL). |
| **Linting / format** | `ruff` (lint+format, very fast), `black`, `isort`, `flake8`, `pylint` | `ruff` has largely consolidated this space — one tool, near-instant. |
| **Typing** | `mypy`, `pyright`/`pylance`, `pydantic`, `typing`/`typing_extensions` | `pyright` is faster + better inference; `mypy` is the reference impl. |
| **Testing** | `pytest`, `hypothesis` (property-based), `pytest-asyncio`, `coverage`, `vcrpy`/`respx` (mock HTTP) | `pytest` is the standard; mock LLM calls so tests are deterministic + free. |
| **Concurrency** | `asyncio`, `anyio`, `httpx` (async HTTP), `concurrent.futures`, `multiprocessing`, `trio` | Match the model to the bottleneck: async for I/O, processes for CPU. |
| **Data validation** | `pydantic` v2, `dataclasses`, `attrs`, `marshmallow` | `pydantic` v2 (Rust core) is fast and the de-facto LLM I/O contract. |
| **CLI / config** | `typer`/`click`, `argparse`, `pydantic-settings`, `hydra`, `dynaconf` | `hydra` shines for ML experiment config; `typer` for clean CLIs. |
| **Web / serving** | `fastapi`+`uvicorn`, `starlette`, `litestar`, `flask` | `fastapi` is the default for async ML APIs (typed, OpenAPI, streaming). |
| **Debugging / profiling** | `pdb`/`ipdb`, `py-spy`, `scalene`, `line_profiler`, `memory_profiler`, `logging` | `py-spy` profiles a running process without code changes — great in prod. |
| **CI / quality gates** | GitHub Actions, `pre-commit`, `tox`/`nox`, semantic-release | `pre-commit` enforces lint/format/type locally before CI. |

**House idioms that signal seniority:** generators over building giant lists;
context managers for resource lifecycles; `pathlib` over `os.path`; `dataclass`/
`pydantic` over loose dicts; structured logging over `print`; dependency
injection over globals; small pure functions that are trivially testable.

## 5. Worked example

A resilient **async LLM client** with typed config, retries+backoff, timeouts,
structured output via `pydantic`, and bounded concurrency — the kind of utility
that underpins every AI app.

```python
"""resilient_llm.py — production-shaped async LLM helper (idiomatic, testable)."""
from __future__ import annotations

import asyncio
import logging
import random
from dataclasses import dataclass

import httpx
from pydantic import BaseModel, Field, ValidationError

logger = logging.getLogger(__name__)


class Sentiment(BaseModel):
    """Typed contract for the model's structured output."""
    label: str = Field(pattern="^(positive|negative|neutral)$")
    confidence: float = Field(ge=0.0, le=1.0)


@dataclass(frozen=True, slots=True)
class ClientConfig:
    base_url: str
    api_key: str
    model: str = "claude-haiku-4-5"
    max_retries: int = 4
    timeout_s: float = 30.0
    max_concurrency: int = 8


class LLMClient:
    """Async client: timeouts, retry w/ exponential backoff + jitter, bounded fan-out."""

    def __init__(self, cfg: ClientConfig) -> None:
        self._cfg = cfg
        self._sem = asyncio.Semaphore(cfg.max_concurrency)
        self._http = httpx.AsyncClient(
            base_url=cfg.base_url,
            timeout=cfg.timeout_s,
            headers={"x-api-key": cfg.api_key},
        )

    async def __aenter__(self) -> "LLMClient":
        return self

    async def __aexit__(self, *exc: object) -> None:
        await self._http.aclose()

    async def _post(self, payload: dict) -> dict:
        """One request with retry on transient (429/5xx/network) errors."""
        for attempt in range(self._cfg.max_retries):
            try:
                resp = await self._http.post("/v1/messages", json=payload)
                if resp.status_code in (429, 500, 502, 503, 504):
                    raise httpx.HTTPStatusError("transient", request=resp.request, response=resp)
                resp.raise_for_status()
                return resp.json()
            except (httpx.HTTPStatusError, httpx.TransportError) as e:
                if attempt == self._cfg.max_retries - 1:
                    logger.error("giving up after %d attempts: %s", attempt + 1, e)
                    raise
                backoff = 2**attempt + random.uniform(0, 1)  # jitter avoids thundering herd
                logger.warning("retry %d in %.1fs (%s)", attempt + 1, backoff, e)
                await asyncio.sleep(backoff)
        raise RuntimeError("unreachable")

    async def classify(self, text: str) -> Sentiment:
        async with self._sem:  # cap in-flight requests
            data = await self._post({
                "model": self._cfg.model,
                "max_tokens": 64,
                "messages": [{"role": "user", "content": f"Classify sentiment as JSON: {text}"}],
            })
        raw = data["content"][0]["text"]
        try:
            return Sentiment.model_validate_json(raw)  # validate the model's output
        except ValidationError as e:
            raise ValueError(f"model returned malformed output: {raw!r}") from e


async def main() -> None:
    cfg = ClientConfig(base_url="https://api.example.com", api_key="…")
    texts = ["I love this!", "This is broken.", "It's fine, I guess."]
    async with LLMClient(cfg) as client:
        results = await asyncio.gather(*(client.classify(t) for t in texts))
    for t, r in zip(texts, results):
        print(f"{t!r:30} -> {r.label} ({r.confidence:.2f})")


if __name__ == "__main__":
    logging.basicConfig(level=logging.INFO)
    asyncio.run(main())
```

A matching deterministic test (no network, no key):

```python
# test_resilient_llm.py
import pytest
from resilient_llm import Sentiment

def test_sentiment_validates_label():
    s = Sentiment.model_validate_json('{"label": "positive", "confidence": 0.9}')
    assert s.label == "positive"

def test_sentiment_rejects_bad_label():
    with pytest.raises(Exception):
        Sentiment.model_validate_json('{"label": "ecstatic", "confidence": 0.9}')

def test_confidence_bounds():
    with pytest.raises(Exception):
        Sentiment.model_validate_json('{"label": "neutral", "confidence": 2.0}')
```

What makes this *idiomatic*: frozen `slots` dataclass config, async context
manager for cleanup, a semaphore to bound concurrency, retry with **jitter**, and
`pydantic` to make the LLM's output a validated contract rather than a hopeful
`json.loads`.

## 6. How to learn it

**Beginner (0–3 months).** Master core syntax, the data model, comprehensions,
generators, and the stdlib (`itertools`, `collections`, `pathlib`, `functools`).
Write small CLIs. *Milestone:* a tested CLI tool published to PyPI with `uv`.

**Intermediate / job-ready (3–9 months).** Type everything (`mypy`/`pyright`);
adopt `pytest` + `hypothesis`; build async I/O code with `httpx`/`asyncio`;
wrap an LLM API in a resilient client (the example above); set up `ruff` +
`pre-commit` + GitHub Actions CI. *Milestone:* a FastAPI service with tests,
types, CI, structured logging, and graceful error handling — green build.

**Expert (9+ months).** Profile and optimize hot paths (`py-spy`, `scalene`);
design clean module boundaries and stable interfaces; handle concurrency
correctly (cancellation, backpressure, timeouts); package + version + release
libraries others depend on; mentor via code review. *Milestone:* you own a
library or service that other teams build on, with a deprecation policy and
99.9% reliability.

## 7. Interview signals

Interviewers probe whether you write code *people can live with*.

- **"When would you use threads vs processes vs asyncio?"** Strong answer ties it
  to the bottleneck: async/threads for I/O-bound (the GIL releases during I/O);
  processes for CPU-bound; asyncio when you need thousands of concurrent I/O ops
  cheaply. Bonus: mention the GIL explicitly and that LLM workloads are I/O-bound.
- **"How do you make an unreliable API call robust?"** Timeouts, retries with
  exponential backoff + jitter, idempotency keys, circuit breakers, bounded
  concurrency, and observability — not just a bare `try/except`.
- **"How do you test code that calls an LLM?"** Mock the HTTP layer (`respx`/
  `vcrpy`), assert on the *contract* (`pydantic` validation), keep tests
  deterministic; separate unit tests from a small set of live integration tests.
- **Live debugging.** They hand you broken code; they watch your process — do you
  read the traceback, form a hypothesis, add a print/breakpoint, bisect? Calm,
  systematic debugging is the strongest possible signal.
- **Code review.** "Critique this PR." A strong candidate flags missing tests,
  untyped boundaries, swallowed exceptions, and unclear names — kindly.
