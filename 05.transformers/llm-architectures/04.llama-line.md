# 04 · The LLaMA line — the open decoder backbone

> **Intuition.** GPT-3 showed scale works but kept the weights closed. Meta's
> LLaMA (2023) shipped a *compute-efficient, openly-available* decoder family
> that, by training smaller models on **more tokens** (Chinchilla-style), matched
> much larger ones. Its architecture — **RMSNorm + RoPE + SwiGLU + GQA** — became
> the de-facto template that Mistral, Qwen, Gemma, Yi and most open models copy.

This file is the keystone: learn these four ingredients and you understand 80% of
every modern open LLM.

---

## 1. The four ingredients (and their components)

A LLaMA block, in words: `x → RMSNorm → RoPE-attention(GQA) → +residual →
RMSNorm → SwiGLU-FFN → +residual`. **Pre-norm** throughout, **no biases**.

### (a) RMSNorm — `06.rmsnorm.py`
Replace LayerNorm with **Root-Mean-Square Norm**: drop the mean-centering and the
bias, keep only the rescaling. Cheaper, and empirically just as stable:

$$\text{RMSNorm}(x) = \frac{x}{\sqrt{\tfrac{1}{d}\sum_i x_i^2 + \epsilon}} \odot g$$

### (b) RoPE — Rotary Position Embeddings — `01.rope.py`
No additive position vectors. Instead **rotate** each query/key by an angle
proportional to its absolute position; the dot product then depends only on the
*relative* offset. Free (no params), and extends to longer contexts via NTK/YaRN
scaling — exactly how LLaMA-3.1 reaches 128k. Pair dims into 2-D planes with
frequency $\theta_i = \text{base}^{-2i/d}$ and rotate by $m\theta_i$ at position $m$.

### (c) SwiGLU FFN — `05.swiglu.py`
A **gated** feed-forward layer: one linear branch is gated (multiplied) by a
SiLU-activated branch, then projected down. Better quality per param than ReLU/GELU
MLPs (hidden dim is scaled by ⅔ to keep the param budget):

$$\text{SwiGLU}(x) = \big(\text{SiLU}(xW_1) \odot xW_3\big)\,W_2,\qquad \text{SiLU}(z)=z\,\sigma(z)$$

### (d) GQA — Grouped-Query Attention — `03.gqa_mqa.py`
Multiple query heads **share** a smaller number of key/value heads. This shrinks
the **KV cache** (`08.kv_cache.py`) — the memory bottleneck of long-context
decoding — with negligible quality loss. MQA (1 KV head) is the extreme; GQA
(e.g. 8 KV groups) is the sweet spot LLaMA-2-70B and LLaMA-3 adopt.

## 2. The releases

### LLaMA-1 (Feb 2023, 7B/13B/33B/65B)
Established the recipe above. Key thesis: **train longer on more tokens** — the
7B saw ~1T tokens — so a small model is cheap to *serve* while still strong.
Context 2048. SentencePiece BPE, 32k vocab. Research-only license; weights leaked
and sparked the open-LLM explosion.

### LLaMA-2 (July 2023, 7B/13B/70B)
Pretrained on **2T tokens**, context **4096**, **GQA on the 34B/70B**. Shipped
**Llama-2-Chat**: SFT + **RLHF** with two reward models (helpfulness + safety)
and **Ghost Attention (GAtt)** to keep system instructions across turns.
Commercial-friendly Llama-2 license.

### Code Llama (Aug 2023, 7B/13B/34B/70B)
LLaMA-2 continued-trained on code. Adds **infilling / Fill-in-the-Middle (FIM)**
(predict a middle span given a prefix and suffix — essential for IDE completion),
long-context fine-tuning via **RoPE base rescaling** (up to ~100k), and
Instruct/Python variants.

### LLaMA-3 (Apr 2024, 8B/70B)
Bigger tokenizer: **128k-vocab tiktoken-style BPE** (more efficient encoding,
better multilingual/code). **GQA on all sizes.** Trained on **15T+ tokens**,
context 8192. A large quality jump from better data + tokenizer.

### LLaMA-3.1 (July 2024, 8B/70B/**405B**)
The 405B is the **largest openly-available model to date** at release. Context
extended to **128k** via RoPE scaling, multilingual, with strong tool-use and a
permissive-ish Llama-3.1 license. 3.2 (vision + small on-device) and 3.3 (70B
tuned to ~405B quality) follow the same backbone.

## 3. Data & scaling

LLaMA's bet was **Chinchilla-informed**: for a *fixed training budget*
≈20 tokens/param is compute-optimal, but for *deployment* you deliberately
**over-train** small models far past that ratio so inference is cheap (LLaMA-3-8B
on 15T tokens is ~1875 tok/param). See scaling laws in
`11.training-and-alignment.md`.

---

## 4. Strengths / limits

Strengths: simple, open, fast to serve, and the architecture that the whole
ecosystem tools around (every quantizer, fine-tuner, and serving engine targets
it first). Limits: dense (no MoE through 3.1, so all params fire every token);
licenses carry some restrictions (not pure Apache); the frontier 405B still needs
serious hardware. Mistral/Qwen/DeepSeek build *sparsity* (`05`, `06`) on top of
this base to push past dense limits.
