## 1. What it is

A deep, end-to-end understanding of the **transformer** — the architecture
under every modern LLM — and the surrounding model landscape. Concretely:
self-attention, multi-head / GQA / MQA, positional encodings (RoPE/ALiBi), the
feed-forward block, tokenization, context windows, the KV-cache, sampling/
decoding strategies, and scaling laws. Plus a working map of the model zoo (GPT,
Claude, Llama, Mistral, Qwen, DeepSeek, Gemma) and their tradeoffs.

It exists because **every downstream decision flows from how transformers
actually work**: your context budget, latency, cost, the choice to fine-tune vs
prompt, which model to pick, why a prompt blows up token count, why long context
degrades. Treating the model as a magic box caps your ceiling as an engineer.

## 2. Why employers want it

R1/R6 list transformer/LLM knowledge as table stakes; Mistral and NVIDIA
interviews probe attention internals directly. The signal:

- **You make architecture-aware tradeoffs.** "Why is this slow at long context?"
  → you reason about the quadratic attention cost and the KV-cache size, not
  guesses.
- **You debug LLM behavior from first principles.** Tokenization quirks,
  position-extrapolation failures, repetition loops — you trace them to a
  mechanism.
- **You can read and reproduce the field.** New models ship monthly; you parse a
  model card and know what GQA, SwiGLU, RoPE-scaling, or MoE *mean* for you.

## 3. Mental model

A decoder-only LLM is a stack of identical **transformer blocks** applied to a
sequence of token embeddings, predicting the next token at every position.

```
tokens ─► embed (+ positional info)
        ─► [ block ] × N           ┐ each block:
        ─► final RMSNorm           │   x += Attention(RMSNorm(x))   (mix across positions)
        ─► linear → softmax        │   x += FFN(RMSNorm(x))         (mix across features)
        ─► next-token distribution ┘
```

**Self-attention** is the one idea to truly own. Each token forms a **query**
$q$, **key** $k$, and **value** $v$. The output at position $i$ is a weighted
average of all values, weighted by query–key similarity:

$$
\mathrm{Attn}(Q,K,V) = \mathrm{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}} + M\right)V
$$

- $QK^\top$ is the $n\times n$ similarity matrix — **this is the quadratic
  cost** in sequence length $n$.
- $\sqrt{d_k}$ keeps the logits from saturating the softmax.
- $M$ is the **causal mask**: $-\infty$ above the diagonal so a token can't
  attend to the future. This is what makes generation autoregressive.

**Multi-head**: run $h$ attentions in parallel on slices of the hidden dim, each
learning a different relation, then concatenate. **GQA/MQA** share key/value
heads across query heads to shrink the KV-cache (the big inference-memory win).

**The FFN** ($x \to W_2\,\phi(W_1 x)$, with $\phi$ = GELU/SwiGLU) is where most
parameters and most "knowledge" live; attention *routes*, the FFN *computes*.

**KV-cache**: during generation, keys and values for past tokens never change,
so you cache them and only compute attention for the new token. This turns an
$O(n^2)$ regeneration into $O(n)$ per step — and the cache size
($2 \cdot n \cdot \text{layers} \cdot d_{kv}$) is the dominant memory cost at
long context.

**Scaling laws** (Kaplan; Chinchilla): loss falls as a power law in params,
data, and compute. Chinchilla's lesson — most early models were *undertrained*;
for a fixed compute budget, scale data ~proportionally to params (~20 tokens per
param as a rule of thumb).

## 4. The landscape

**Positional encoding** — transformers are permutation-invariant without it.
Sinusoidal (original) → learned → **RoPE** (rotary, rotates q/k by position;
dominant, extrapolates with scaling) → **ALiBi** (linear attention bias; trains
short, runs long). NoPE (no positional encoding) works in some decoder setups.

**Attention variants** — MHA → **MQA** (1 KV head) → **GQA** (a few KV groups;
the standard middle ground) → **MLA** (DeepSeek's latent compression) →
**sliding-window** (Mistral; local attention) → **FlashAttention** (exact, but
IO-aware tiling — a kernel optimization, not a math change). Linear/SSM
alternatives: **Mamba** (selective state space), **RWKV** (RNN-like, parallel
train).

**Normalization & activations** — LayerNorm → **RMSNorm** (cheaper, standard
now); pre-norm beats post-norm for deep stacks. GELU → **SwiGLU** (gated, in
Llama/Mistral/Qwen FFNs).

**Mixture-of-Experts (MoE)** — replace the dense FFN with many experts, route
each token to a few (top-k). Big total params, small *active* params per token →
quality of a large model at the cost of a small one (Mixtral, DeepSeek-V3,
Qwen-MoE).

**Tokenization** — BPE (GPT), WordPiece, **SentencePiece/Unigram** (Llama). Byte
fallback handles any input. Tokenization explains "why does emoji/code/non-
English cost more tokens" and many off-by-one prompt bugs.

**Decoding/sampling** — greedy, beam (rare for chat), **temperature**, **top-k**,
**top-p (nucleus)**, **min-p**, repetition/frequency penalties. Speculative
decoding (draft model proposes, big model verifies) speeds generation with no
quality loss.

**Model landscape (catalogue).**

| Family | Org | Open? | Notable |
|---|---|---|---|
| GPT-4/4o/5 | OpenAI | No | frontier; multimodal |
| **Claude** (Opus/Sonnet/Haiku) | Anthropic | No | long context, agentic, tool use |
| Llama 3/4 | Meta | Weights | the open default; GQA, RoPE |
| Mistral / Mixtral | Mistral | Weights | sliding-window; MoE |
| Qwen 2.5/3 | Alibaba | Weights | strong multilingual/code; MoE variants |
| DeepSeek V3/R1 | DeepSeek | Weights | MLA, MoE, RL-for-reasoning |
| Gemma / Gemini | Google | Mixed | Gemma open, Gemini hosted |

## 5. Worked example

Self-attention from scratch in NumPy — the clearest way to *see* the mechanism.
Then the idiomatic PyTorch one-liner it corresponds to.

```python
"""attention_from_scratch.py — causal self-attention by hand. CPU, exit 0."""
import numpy as np

rng = np.random.default_rng(0)

def softmax(x, axis=-1):
    x = x - x.max(axis=axis, keepdims=True)        # numerical stability
    e = np.exp(x)
    return e / e.sum(axis=axis, keepdims=True)

def causal_self_attention(X, Wq, Wk, Wv):
    """X: (n, d_model). Single head. Returns (n, d_v)."""
    Q, K, V = X @ Wq, X @ Wk, X @ Wv               # project to q/k/v
    d_k = Q.shape[-1]
    scores = (Q @ K.T) / np.sqrt(d_k)              # (n, n) similarity
    n = scores.shape[0]
    mask = np.triu(np.ones((n, n)), k=1).astype(bool)  # upper triangle = future
    scores[mask] = -np.inf                          # causal mask
    weights = softmax(scores, axis=-1)             # row i = how token i attends
    return weights @ V                              # weighted average of values

n, d_model, d_k = 4, 8, 8
X = rng.normal(size=(n, d_model))
Wq, Wk, Wv = (rng.normal(size=(d_model, d_k)) * 0.1 for _ in range(3))
out = causal_self_attention(X, Wq, Wk, Wv)
print("output shape:", out.shape)                  # (4, 8)
# Token 0 can only attend to itself; token 3 attends to 0..3 — verify the mask:
W = softmax(np.where(np.triu(np.ones((n, n)), 1).astype(bool), -np.inf,
                     (X @ Wq) @ (X @ Wk).T / np.sqrt(d_k)))
print("row 0 weights:", W[0].round(2))             # [1. 0. 0. 0.]
```

The equivalent in PyTorch (what production code actually calls — fused, batched,
GPU-accelerated):

```python
import torch.nn.functional as F
# X: (batch, heads, seq, d_k); is_causal applies the mask, plus a fused kernel.
out = F.scaled_dot_product_attention(Q, K, V, is_causal=True)  # FlashAttention under the hood
```

Same math — the production path is `scaled_dot_product_attention`, which dispatches
to FlashAttention. Understanding the NumPy version lets you reason about *why*
the fused kernel and the KV-cache matter.

## 6. How to learn it

**Beginner (0–3 months).** Watch Karpathy's *Let's build GPT* and **build
nanoGPT** end to end; read *The Illustrated Transformer* (Alammar) and the
*Annotated Transformer*. *Milestone:* a working char-level GPT you trained and
can sample from, with the attention you wrote by hand.

**Intermediate / job-ready (3–9 months).** Read *Attention Is All You Need*,
RoPE, GQA, FlashAttention, and Chinchilla. Implement KV-cache, sampling
strategies, and RoPE. Read model cards (Llama 3, Mistral, Qwen, DeepSeek-V3) and
explain each architectural choice. *Milestone:* you can diagram a modern decoder
block from memory and justify every component.

**Expert (9+ months).** Track SOTA (MoE routing, long-context tricks, SSMs);
reproduce a paper's mechanism in clean code; reason quantitatively about FLOPs,
memory, and latency for a given config. *Milestone:* you can spec a model/serving
config for a latency/cost target and defend it.

## 7. Interview signals

- **"Walk me through self-attention."** Strong answer derives the QKV/softmax
  formula, explains the scale factor and the causal mask, and notes the $O(n^2)$
  cost — then connects it to the KV-cache at inference.
- **"Why GQA/MQA?"** Shrinks the KV-cache (fewer KV heads) → less memory, higher
  throughput, longer context — at a small quality cost vs full MHA.
- **"How does RoPE let a model handle longer context than it trained on?"**
  Rotary phase is relative and continuous; scaling (NTK/linear/YaRN)
  interpolates positions so attention patterns still resolve.
- **"Temperature vs top-p?"** Temperature reshapes the whole distribution; top-p
  truncates to the smallest set covering probability $p$ then renormalizes. Both
  trade determinism for diversity; describe failure modes (repetition, drift).
- **"What did Chinchilla change?"** For a fixed compute budget, scale data with
  params (~20:1); many earlier models were undertrained.
