# 02 · End-to-End Workflow

> The full lifecycle, in order: **search → load → preprocess (tokenize) →
> fine-tune (Trainer / PEFT) → evaluate → push to Hub → serve**. Every stage
> links to the runnable example that demonstrates it. Builds on the ecosystem map
> in [`01.architecture.md`](01.architecture.md).

This is the canonical recipe an ML engineer runs when adapting an open model to a
task. We use **tiny models + tiny data** so the *shape* is real even though the
scale is toy.

```
 ┌────────┐   ┌──────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────┐   ┌───────┐
 │ SEARCH │──▶│ LOAD │──▶│PREPROCESS│──▶│ FINE-TUNE│──▶│ EVALUATE │──▶│ PUSH │──▶│ SERVE │
 └────────┘   └──────┘   └──────────┘   └──────────┘   └──────────┘   └──────┘   └───────┘
   HfApi      Auto* /     tokenizer      Trainer /      evaluate /     push_to_   pipeline /
   web facets load_dataset .map()        PEFT / TRL     trainer.eval   hub()      TGI / Spaces
```

---

## Stage 1 — Search & choose a model

Decide on a **task** (`pipeline_tag`) and constraints (size, license, language),
then filter. Web facets or the API:

```python
from huggingface_hub import HfApi
api = HfApi()
for m in api.list_models(filter="text-classification", sort="downloads",
                         direction=-1, limit=5):
    print(m.id, m.downloads)
```

Selection checklist: **task head** matches your problem · **license** permits
your use (§4 of the manifest) · **size** fits your hardware · **base vs.
instruct** (chat models want instruct/chat checkpoints) · read the **model card**
for training data, eval, and known biases. → `hub/02.search_and_info.py`,
`transformers/01.pipelines.py`.

---

## Stage 2 — Load the model & data

**Model** (`Auto*` reads `config.json` and picks the class — see architecture §3):

```python
from transformers import AutoTokenizer, AutoModelForSequenceClassification
name = "prajjwal1/bert-tiny"
tok   = AutoTokenizer.from_pretrained(name)
model = AutoModelForSequenceClassification.from_pretrained(name, num_labels=2)
```

**Data** (Arrow-backed, memory-mapped; streamable for big corpora):

```python
from datasets import load_dataset
ds = load_dataset("glue", "sst2")            # DatasetDict: train/validation/test
# or stream:  load_dataset(..., streaming=True) → IterableDataset (no full download)
```

→ `transformers/02.automodel.py`, `datasets/01.load.py`, `datasets/02.stream.py`.

---

## Stage 3 — Preprocess (tokenize)

Map the tokenizer over the dataset. `batched=True` runs the fast Rust tokenizer
in batches; `truncation`/`padding` set the tensor shape. Tokenization is the
bridge from `datasets` → `transformers` (architecture §1).

```python
def preprocess(batch):
    return tok(batch["sentence"], truncation=True, padding="max_length", max_length=64)

tok_ds = ds.map(preprocess, batched=True)
tok_ds = tok_ds.rename_column("label", "labels")          # Trainer expects "labels"
tok_ds.set_format("torch", columns=["input_ids", "attention_mask", "labels"])
```

Use a **`DataCollatorWithPadding`** to pad *per batch* (dynamic padding) instead
of to a global max — faster and less wasted compute. For language modelling use
`DataCollatorForLanguageModeling`. → `tokenizers/`, `datasets/03.map_filter.py`,
`transformers/06.trainer.py`.

---

## Stage 4 — Fine-tune

Three ascending options (architecture §4):

**(a) Full fine-tune with `Trainer`** — updates all weights:
```python
from transformers import Trainer, TrainingArguments
args = TrainingArguments(output_dir="out", num_train_epochs=1,
                         per_device_train_batch_size=8,
                         eval_strategy="epoch", report_to="none")
trainer = Trainer(model=model, args=args,
                  train_dataset=tok_ds["train"], eval_dataset=tok_ds["validation"],
                  compute_metrics=compute_metrics)
trainer.train()
```

**(b) PEFT / LoRA** — freeze the base, train a small adapter (MBs, not GBs).
Best when the model is large or you want many cheap task-specific adapters:
```python
from peft import LoraConfig, get_peft_model
model = get_peft_model(model, LoraConfig(r=8, lora_alpha=16, target_modules=["query","value"]))
model.print_trainable_parameters()      # e.g. 0.3% of params trainable
# …then the same Trainer as above
```

**(c) TRL** — instruction/preference tuning: `SFTTrainer` (supervised
fine-tune on prompt→response), then `DPOTrainer` (align to preference pairs).
TRL wraps `Trainer` and accepts a `peft_config` so SFT and LoRA combine.

→ `transformers/06.trainer.py`, `peft/01.lora_finetune.py`,
`trl/01.sft_trainer.py`, `accelerate/` (the loop underneath).

---

## Stage 5 — Evaluate

Compute task metrics with `evaluate` inside `compute_metrics`, then
`trainer.evaluate()`:

```python
import evaluate, numpy as np
acc = evaluate.load("accuracy")
def compute_metrics(eval_pred):
    logits, labels = eval_pred
    preds = np.argmax(logits, axis=-1)
    return acc.compute(predictions=preds, references=labels)

print(trainer.evaluate())     # {'eval_accuracy': ..., 'eval_loss': ...}
```

Pick metrics by task: **accuracy/F1** (classification), **seqeval** (NER),
**exact-match/F1** (QA), **ROUGE/BLEU** (summarization/translation),
**perplexity** (LM). For generation quality and preference, hold out a prompt set
and compare decoding strategies (architecture §4, `transformers/03.generation.py`).

---

## Stage 6 — Push to the Hub

Share weights **and** a model card. (Needs a write token; the runnable examples
are offline-safe and only *describe* the push unless `HF_TOKEN` is set.)

```python
trainer.push_to_hub()                       # weights + auto card + training args
# or, model + tokenizer directly:
model.push_to_hub("me/bert-tiny-sst2")
tok.push_to_hub("me/bert-tiny-sst2")
# PEFT: adapter only
peft_model.push_to_hub("me/bert-tiny-sst2-lora")
```

Write a real **model card** (`ModelCard` / front-matter: `license`,
`pipeline_tag`, `datasets`, `metrics`) so the Hub shows the right widget and your
model is discoverable. → `hub/03.create_and_push.py`, `hub/04.model_card.py`.

---

## Stage 7 — Serve

Pick by scale:

| Option | What | When |
|---|---|---|
| **`pipeline`** | in-process inference | scripts, notebooks, batch jobs |
| **Gradio / Spaces** | web UI on a Hub repo | demos, sharing, internal tools |
| **TGI** (Text Generation Inference) | production server: continuous batching, paged-attn, streaming | high-throughput LLM serving |
| **optimum (ONNX/OpenVINO)** | export + runtime opt | CPU/edge latency, non-PyTorch runtime |

```python
from transformers import pipeline
serve = pipeline("text-classification", model="me/bert-tiny-sst2")
serve("the movie was great")
```

```python
import gradio as gr
gr.Interface(fn=lambda t: serve(t)[0], inputs="text", outputs="json").launch()
```

TGI (Docker, one line): `docker run --gpus all -p 8080:80 \
ghcr.io/huggingface/text-generation-inference --model-id me/my-llm`, then POST to
`/generate` (OpenAI-compatible `/v1/...` routes available). → `transformers/`,
`diffusers/`, `sentence-transformers/`, and §7 of `01.architecture.md`.

---

## The loop, closed

Search → load → preprocess → fine-tune → evaluate → push → serve, then **iterate**:
a served model surfaces failures, which become new eval cases and new training
data, which feed the next fine-tune. The Hub is the system of record at every
hop — the same repo id flows from `load_dataset`/`from_pretrained` at the start to
`push_to_hub`/serve at the end.
