## What it is

**Claude Code is an agentic coding tool.** It reads your codebase, edits files,
runs commands, and integrates with your development tools — driven by natural
language. You describe an outcome ("write tests for the auth module, run them,
and fix any failures"); Claude Code plans an approach, executes it across many
files and tools, observes the results, and iterates until done.

This is the distinction from an autocomplete assistant: Claude Code is an
**agent**. It runs a loop — gather context, decide, act with tools, observe,
repeat — rather than emitting a single completion. The model is in the driver's
seat, choosing which tool to call next based on what it has seen so far.

## Where it runs

The same underlying "Claude Code engine" is exposed through many surfaces, and
your `CLAUDE.md` files, settings, and MCP servers carry across all of them:

| Surface | What it is |
|---|---|
| **Terminal CLI** | The full-featured `claude` command. Edit files, run commands, pipe in logs, run in CI (`claude -p "..."`). |
| **IDE extensions** | VS Code / Cursor and JetBrains plugins with inline diffs, `@`-mentions, plan review. |
| **Desktop app** | Standalone app: visual diff review, parallel sessions, scheduled tasks. |
| **Web / mobile** | `claude.ai/code` in a browser and the iOS app, for long-running tasks and repos you don't have locally. |
| **CI / chat / GitHub** | GitHub Actions, GitLab CI/CD, automatic PR review, Slack-to-PR, and the **Agent SDK** for building custom agents on the same tools. |

Because it follows the Unix philosophy, the CLI is *composable*:

```bash
tail -200 app.log | claude -p "Slack me if you see any anomalies"
git diff main --name-only | claude -p "review these changed files for security issues"
```

## The product surface (capabilities)

* **Build features and fix bugs** — plan, write code across files, verify it runs.
* **Git workflows** — stage changes, write commit messages, create branches, open PRs.
* **MCP integration** — connect external tools/data (issue trackers, databases,
  design tools) via the open [Model Context Protocol](05.mcp.md).
* **Customization** — `CLAUDE.md` project instructions and auto-memory; **skills**
  (packaged repeatable workflows / slash commands); **hooks** (shell commands
  before/after actions).
* **Agent teams & sub-agents** — spawn specialized [sub-agents](06.skills-subagents.md)
  that work in their own context windows and return summaries.
* **Scheduling** — routines / scheduled tasks / `/loop` for recurring work.

## The mental model this section teaches

Strip away the surfaces and the engine is four cooperating pieces:

1. **An agent loop** that calls the model, runs the tools it asks for, feeds the
   results back, and repeats ([`02.architecture.md`](02.architecture.md)).
2. **A tool system** — Read, Write, Edit, Bash, Glob, Grep, Agent (sub-agents),
   TodoWrite — with typed schemas and parallel-safe scheduling
   ([`03.tools.md`](03.tools.md)).
3. **A permission layer** — allow/ask/deny rules, modes (plan, acceptEdits,
   bypass), sandboxing, and hooks ([`04.permissions.md`](04.permissions.md)).
4. **Context management** — a frozen system prompt, streaming, a token budget,
   and compaction of old turns ([`02.architecture.md`](02.architecture.md)).

The runnable mini-agents in [`../python/`](../python/) and [`../ruby/`](../ruby/)
implement exactly these four pieces — small enough to read in an afternoon, real
enough to run end-to-end (including a live MCP round-trip) with no API key.
