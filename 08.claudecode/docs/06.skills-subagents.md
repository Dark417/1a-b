# 06. Skills, sub-agents & slash commands

> Clean-room: built from the public Claude Code sub-agents/skills docs and
> Anthropic's agent-design guidance. Citations: [`07.references.md`](07.references.md).

Three customization mechanisms let you scale a coding agent past a single
general-purpose loop: **skills** (load instructions on demand), **sub-agents**
(delegate work to isolated context windows), and **slash commands** (named,
reusable prompts).

## Skills

A **skill** packages task-specific expertise — a workflow, conventions, a
checklist — that the agent loads **only when relevant**. Each skill is a folder
with a `SKILL.md` (plus optional supporting files). The mechanism is *progressive
disclosure*:

* The skill's short **description** sits in the model's context by default, so
  the model knows the skill *exists* and roughly when it applies.
* When a task matches, the model **reads the full `SKILL.md`** on demand, pulling
  the detailed instructions into context only then.

This keeps the base system prompt small while making deep, specialized guidance
discoverable. A `SKILL.md` carries YAML frontmatter (a `name` and a
trigger-oriented `description`) followed by the instructions:

```markdown
---
name: review-pr
description: >-
  Review a pull request for correctness and style. Use when the user asks to
  review a PR, a diff, or changed files before merging.
---
# How to review a PR
1. Diff the branch against main...
2. Check for...
```

(This repository itself is authored under a skill —
[`.claude/skills/tutorial-architect/SKILL.md`](../../.claude/skills/tutorial-architect/SKILL.md) —
a concrete example of the same format.)

## Sub-agents

A **sub-agent** is a specialized assistant that runs in its **own context
window**, with its own system prompt, its own (often narrower) tool access, its
own permissions, and potentially a cheaper model. The main agent **delegates** a
task to it via the **Agent / Task tool**; the sub-agent works independently and
returns only its **summary** to the main conversation.

Why this matters:

* **Context preservation.** A research/exploration task can produce thousands of
  tokens of search results and file contents the main agent will never reference
  again. Running it in a sub-agent keeps that noise out of the main window — the
  main agent sees just the conclusion.
* **Constraint enforcement.** Limiting a sub-agent's tools (e.g. read-only)
  bounds what it can do.
* **Cost control.** Route cheap, parallelizable work (search, triage) to a faster
  model while the main loop stays on the strong model — which also preserves the
  prompt cache, since the main loop's model never changes.
* **Specialization.** A focused system prompt makes a sub-agent good at one
  domain (e.g. a code-reviewer, a test-writer).

Sub-agents are defined like skills — a markdown file with frontmatter (name,
description, allowed tools, model) and a system prompt — and the main agent uses
each sub-agent's **description** to decide when to delegate, exactly as it uses a
tool description to decide when to call a tool.

```
main agent ──delegates──▶ research sub-agent  (own context, read-only tools, Haiku)
     ▲                          │
     └──── returns summary ◀─────┘   (main context stays clean)
```

> The mini-agent exposes the loop, tool registry, and permission gate that a
> sub-agent implementation builds on: a `Task` tool would spawn a fresh `Agent`
> with a scoped `ToolRegistry` and `PermissionGate`, run it on the delegated
> task, and return its final text — a few dozen lines on top of the existing
> pieces. It is documented here as the natural extension point.

## Slash commands

A **slash command** is a named, reusable prompt — `/review-pr`, `/deploy-staging`
— that expands into a fuller instruction (often parameterized). It's the
ergonomic front door to a skill or a canned workflow: instead of retyping a long
prompt, you invoke the command. In Claude Code's model, skills and slash commands
overlap — a skill can *be* a slash command, packaging a repeatable team workflow
behind a short name.

## How they fit together

* **Skills** keep specialized *instructions* out of the base prompt until needed.
* **Sub-agents** keep specialized *work* out of the main *context window*.
* **Slash commands** give both a short, memorable invocation.

All three serve the same goal as the context-management techniques in
[`02.architecture.md`](02.architecture.md): keep the working context small and
relevant, and bring in detail (instructions, or whole sub-conversations) only on
demand.
