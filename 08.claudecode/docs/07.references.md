# 07. References

> **Clean-room statement.** Everything in this section ([`08.claudecode/`](../))
> — the docs and the runnable mini-agents in [`../python/`](../python/) and
> [`../ruby/`](../ruby/) — is **original educational work**, synthesized from the
> **public** sources below. **No proprietary or leaked Anthropic source code was
> downloaded, copied, or redistributed.** The mini-agents are a clean-room
> *re-implementation of the architecture*, written from scratch to teach the
> ideas, and are clearly labeled as such throughout.

## Official Claude Code documentation

- **Claude Code — Overview.** What Claude Code is (agentic coding tool), where it
  runs (terminal, IDE, desktop, web, CI/chat/GitHub), and its capabilities.
  <https://code.claude.com/docs/en/overview>
- **Claude Code — Settings.** `settings.json` structure, scopes/precedence,
  permission modes, and allow/ask/deny permission rules with allowlist patterns.
  <https://code.claude.com/docs/en/settings>
- **Claude Code — Hooks.** Hook events (PreToolUse, PostToolUse, Stop,
  UserPromptSubmit, SessionStart/End), matchers, JSON input/output, exit-code
  semantics. <https://code.claude.com/docs/en/hooks>
- **Claude Code — Sub-agents.** Specialized assistants with their own context
  window, tools, permissions, and model; delegation and context savings.
  <https://code.claude.com/docs/en/sub-agents>
- **Claude Code — Skills.** Skill folders, `SKILL.md` format, progressive
  disclosure / on-demand loading. <https://code.claude.com/docs/en/skills>
- **Claude Code — MCP.** Connecting Claude Code to external tools/data via MCP;
  server discovery and usage. <https://code.claude.com/docs/en/mcp>
- **Claude Code — Memory (CLAUDE.md).** Persistent project instructions and auto
  memory. <https://code.claude.com/docs/en/memory>
- **Claude Code — CLI reference.** Commands, flags, `-p` non-interactive mode.
  <https://code.claude.com/docs/en/cli-reference>
- **Claude Agent SDK — Overview.** Building custom agents on Claude Code's tools.
  <https://code.claude.com/docs/en/agent-sdk/overview>

## Model Context Protocol (open standard)

- **MCP — Architecture overview.** Host/client/server model, data vs transport
  layers, JSON-RPC 2.0, lifecycle (`initialize` → `notifications/initialized`),
  capability negotiation, and the tools/resources/prompts primitives — with the
  worked `tools/list` / `tools/call` message sequence.
  <https://modelcontextprotocol.io/docs/concepts/architecture>
- **MCP — Specification.** The normative protocol spec (versioned, e.g.
  `2025-06-18`). <https://modelcontextprotocol.io/specification/latest>
- **MCP — Server concepts** (tools, resources, prompts) and **Client concepts**
  (sampling, elicitation, logging).
  <https://modelcontextprotocol.io/docs/concepts/server-concepts> ·
  <https://modelcontextprotocol.io/docs/concepts/client-concepts>
- **MCP — Reference servers.** Example implementations (filesystem, etc.).
  <https://github.com/modelcontextprotocol/servers>

## Anthropic API documentation (the engine underneath)

- **Tool use overview.** Tool definition schema (`name`/`description`/
  `input_schema`), `tool_choice`, the `tool_use` / `tool_result` round-trip, the
  agentic loop, and parallel tool calls.
  <https://docs.claude.com/en/docs/agents-and-tools/tool-use/overview>
- **Streaming.** Server-sent event types (`content_block_delta`, `message_delta`,
  …) and the streaming helpers used for incremental output.
  <https://docs.claude.com/en/docs/build-with-claude/streaming>
- **Compaction.** Server-side summarization of earlier context for long
  conversations. <https://docs.claude.com/en/docs/build-with-claude/compaction>
- **Context editing.** Pruning stale tool results / thinking blocks.
  <https://docs.claude.com/en/docs/build-with-claude/context-editing>
- **Prompt caching.** Prefix-match caching and why the system prompt is kept
  byte-stable. <https://docs.claude.com/en/docs/build-with-claude/prompt-caching>
- **Token counting.** The `count_tokens` endpoint (the real basis for the
  mini-agent's approximate budget).
  <https://docs.claude.com/en/docs/build-with-claude/token-counting>
- **Bash tool / Text editor tool.** Reference designs for shell and file-editing
  tools. <https://docs.claude.com/en/docs/agents-and-tools/tool-use/bash-tool> ·
  <https://docs.claude.com/en/docs/agents-and-tools/tool-use/text-editor-tool>
- **Models overview.** Current model IDs / context windows (the mini-agent's
  optional real backend defaults to `claude-opus-4-8` with adaptive thinking).
  <https://docs.claude.com/en/docs/about-claude/models/overview>

## On clean-room re-implementation

The goal here is pedagogical: build the *smallest faithful model* of the
architecture from public descriptions, so a reader understands Claude Code by
reading ~1,000 lines that actually run. Where this re-implements a proprietary
system, it does so from the public documentation above and cites it — never by
copying internal source. This mirrors the house standard in
[`.claude/skills/tutorial-architect/SKILL.md`](../../.claude/skills/tutorial-architect/SKILL.md):
"build a clean-room minimal version from public documentation and cite sources;
never copy leaked/proprietary source."

*Documentation URLs reflect the public sources consulted while authoring this
section (June 2026). Anthropic's docs moved from `docs.anthropic.com` /
`docs.claude.com` to `code.claude.com` for the Claude Code pages; both forms
appear in the wild and redirect appropriately.*
