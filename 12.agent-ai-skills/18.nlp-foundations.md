## 1. What it is

**Natural Language Processing (NLP)** is the discipline of getting computers to
represent, understand, and generate human language. "NLP foundations" is the
*pre-LLM* core that still runs underneath every modern system: how text becomes
tokens, how tokens become vectors, the canonical tasks (classification, NER, QA,
summarization, sequence labeling), and how you *measure* whether a system is any
good (BLEU, ROUGE, F1, perplexity).

It exists as a named skill because **LLMs are NLP systems**, not magic. The
fundamentals explain the behavior you actually debug in production: why a model
splits "tokenization" into three sub-words and mangles a rare API name; why a
Japanese prompt costs 3× the tokens of the English one; why your "summarizer"
scores 0.4 ROUGE but reads fine (and what that mismatch means); why cosine
similarity on embeddings retrieves the wrong passage. Knowing the toolkit *below*
the transformer is what separates someone who *uses* an LLM from someone who can
*diagnose* one.

## 2. Why employers want it

Section 11 places this at #18 and notes NLP is a *named* requirement in roughly a
fifth of postings — and *implicit* almost everywhere, because every LLM task is
an NLP task wearing a chat interface. Employers read the signal as:

- **You understand tokenization quirks** — the root cause of a huge class of
  prompt bugs (off-by-one token budgets, broken JSON on rare tokens, multilingual
  cost blow-ups, the "strawberry has how many r's" failure).
- **You can design evaluation** — you know that BLEU/ROUGE measure n-gram
  overlap, not correctness, and you reach for the right metric (or an LLM judge)
  for the task.
- **You can fall back to classics** — a TF-IDF + logistic-regression classifier
  is faster, cheaper, and often *better* than an LLM for a narrow text task. That
  judgment is senior.
- **You speak the vocabulary** — embeddings, n-grams, sequence labeling, BPE,
  perplexity — the shared language of the field.

## 3. Mental model

NLP is a **pipeline from raw text to a decision**, and almost every stage has a
classic and a neural version:

```
 raw text
   │  normalize (lowercase? unicode NFC? strip?)
   ▼
 TOKENIZE  ──►  words │ subwords (BPE/WordPiece/Unigram) │ chars │ bytes
   │
   ▼
 REPRESENT ──►  one-hot │ TF-IDF │ count vectors        (sparse, classic)
   │            word2vec/GloVe/fastText                  (static dense)
   │            contextual (BERT/transformer hidden states) (dynamic dense)
   ▼
 MODEL     ──►  NB/LogReg/SVM │ CRF │ RNN/LSTM │ Transformer
   │
   ▼
 TASK      ──►  classify │ tag (NER/POS) │ generate (MT/summarize) │ rank/retrieve
   │
   ▼
 EVALUATE  ──►  accuracy/F1 │ BLEU/ROUGE/METEOR │ perplexity │ exact-match/SQuAD-F1
```

**Concepts to own cold:**

- **Tokenization is lossy and political.** Word-level → huge vocab + OOV problem.
  Char/byte-level → tiny vocab but long sequences. **Subword** (BPE, WordPiece,
  Unigram/SentencePiece) is the modern compromise: frequent words stay whole,
  rare words split into pieces, *nothing* is OOV. BPE *merges* the most frequent
  adjacent pair repeatedly; Unigram *prunes* from a large vocab by likelihood.
- **The distributional hypothesis** — "a word is known by the company it keeps"
  (Firth). Embeddings operationalize it: words in similar contexts get similar
  vectors. word2vec's skip-gram maximizes the dot-product of a word and its
  context words. The famous `king − man + woman ≈ queen` falls out of this.
- **Static vs. contextual embeddings.** word2vec/GloVe give one vector per word
  ("bank" is fixed). BERT-style models give a vector *per occurrence* — "river
  bank" and "savings bank" differ. LLMs are the contextual extreme.
- **Sequence labeling** assigns a tag to every token (POS, NER via BIO tagging:
  `B-PER I-PER O O B-LOC`). A **CRF** layer models tag-to-tag transitions so you
  don't predict `I-PER` after `O`.
- **Evaluation is task-shaped.** Classification → precision/recall/**F1**
  (`F1 = 2PR/(P+R)`). Translation → **BLEU** (n-gram precision + brevity
  penalty). Summarization → **ROUGE** (n-gram/longest-subsequence *recall*).
  Language modeling → **perplexity** = `exp(cross-entropy)`, lower is better. QA →
  exact-match + token-F1 (SQuAD). All of these are proxies; none capture
  "correct."

## 4. The landscape

**Tokenization**
- `tiktoken` (OpenAI BPE), Hugging Face `tokenizers` (fast Rust BPE/WordPiece/
  Unigram), `sentencepiece` (language-agnostic, used by Llama/T5/Gemma), spaCy
  (rule-based linguistic tokenizer). Tradeoff: `tiktoken`/HF for LLM token
  budgeting; spaCy when you need *linguistic* tokens (lemmas, POS).

**Classic representations & models**
- `scikit-learn` — `TfidfVectorizer`, `CountVectorizer`, `LogisticRegression`,
  `LinearSVC`, `MultinomialNB`. Still the right tool for narrow, high-volume,
  latency-sensitive text classification.
- `gensim` — word2vec, fastText, LDA topic models, similarity indexes.

**Linguistic toolkits**
- **spaCy** — production-grade pipelines (tokenize, POS, NER, dependency parse),
  fast, pretrained models. The default industrial toolkit.
- **NLTK** — teaching/research, exhaustive but slow; great for learning concepts.
- **Stanza / CoreNLP** (Stanford) — strong multilingual linguistic annotation.

**Neural / transformer NLP**
- Hugging Face **Transformers** + **Datasets** — BERT/RoBERTa/DeBERTa for
  classification & NER, T5/BART for seq2seq, the whole zoo. → see
  [`../09.huggingface/`](../09.huggingface/).
- **sentence-transformers** — pooled embeddings for semantic search/clustering.

**Evaluation libraries**
- `sacrebleu` (reproducible BLEU/chrF/TER — *use this*, not ad-hoc BLEU),
  `rouge-score`, `evaluate` (HF, unifies many metrics), `seqeval` (entity-level
  F1 for NER), `bert-score` (embedding-based similarity, correlates better with
  humans than BLEU/ROUGE).

**Tradeoff summary:** classic sparse models win on speed/cost/interpretability
for narrow tasks; transformers win on accuracy and transfer; LLMs win on
zero-shot generality but cost the most and are hardest to evaluate. The skill is
knowing which rung of the ladder a problem actually needs.

## 5. Worked example

Two things every NLP engineer should be able to do from scratch: **train a
classic text classifier** and **compute the metrics correctly**. Runs on CPU in
seconds, no downloads.

```python
"""nlp_foundations.py — TF-IDF + LogReg baseline and metric sanity-checks.
Run: python nlp_foundations.py
"""
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import classification_report
from sklearn.pipeline import Pipeline

# --- 1. A tiny sentiment dataset (in real life: load thousands) ---
train_texts = [
    "I love this, absolutely fantastic", "best purchase ever, so happy",
    "great quality and fast shipping",   "terrible, broke on day one",
    "awful experience, would not buy",   "completely useless and slow",
]
train_labels = [1, 1, 1, 0, 0, 0]  # 1=positive, 0=negative

# --- 2. The classic baseline: TF-IDF features -> linear classifier ---
clf = Pipeline([
    # ngram_range=(1,2) -> unigrams + bigrams; sublinear_tf dampens term counts.
    ("tfidf", TfidfVectorizer(ngram_range=(1, 2), sublinear_tf=True)),
    ("lr", LogisticRegression(max_iter=1000)),
])
clf.fit(train_texts, train_labels)

test = ["this is fantastic", "this is terrible and slow"]
print("Predictions:", clf.predict(test))  # -> [1 0]

# --- 3. Inspect what the model learned (interpretability for free) ---
vec, lr = clf.named_steps["tfidf"], clf.named_steps["lr"]
vocab = vec.get_feature_names_out()
coefs = lr.coef_[0]
top_pos = sorted(zip(coefs, vocab), reverse=True)[:3]
top_neg = sorted(zip(coefs, vocab))[:3]
print("most positive features:", [w for _, w in top_pos])
print("most negative features:", [w for _, w in top_neg])

# --- 4. Metrics done right: F1 is the harmonic mean of precision & recall ---
y_true = [1, 1, 0, 0, 1, 0]
y_pred = [1, 0, 0, 1, 1, 0]
print(classification_report(y_true, y_pred, target_names=["neg", "pos"], digits=3))


# --- 5. Tokenization quirk demo: subword splitting + token counting ---
def char_bpe_intuition(word: str) -> list[str]:
    """A toy of WHY rare words fragment: imagine 'token','ization' are merges
    learned from data, but 'ization' of a rare stem is not -> it splits."""
    known_merges = {"token", "ization", "un", "ing"}
    pieces, i = [], 0
    while i < len(word):
        for j in range(len(word), i, -1):   # greedy longest-match (BPE-ish)
            if word[i:j] in known_merges:
                pieces.append(word[i:j]); i = j; break
        else:
            pieces.append(word[i]); i += 1   # fall back to single char
    return pieces


print("subword split:", char_bpe_intuition("tokenization"))  # ['token','ization']
print("rare word:", char_bpe_intuition("zxqvb"))             # all single chars
```

The lesson: the linear baseline is *interpretable* (you can read its top
features), *fast*, and a hard-to-beat reference point you should always build
before reaching for an LLM. And `classification_report` shows F1 ≠ accuracy when
classes are imbalanced or errors asymmetric.

## 6. How to learn it

**Beginner (weeks).** Tokenize/normalize text by hand; build a `CountVectorizer`/
`TfidfVectorizer` + Naive Bayes / LogReg classifier on a public dataset (IMDb,
AG News). Learn precision/recall/F1 by computing them on a confusion matrix
yourself. *Milestone:* a working text classifier with a correct
`classification_report` you can explain line by line.

**Job-ready (1–3 months).** Train word2vec/GloVe and probe analogies; do NER with
spaCy and evaluate with `seqeval` (entity-level, not token-level, F1); fine-tune
a BERT classifier with HF Transformers; compute BLEU with `sacrebleu` and ROUGE
correctly, and *explain why they disagree with human judgment*. Understand BPE vs
WordPiece vs Unigram. *Milestone:* a small NER or QA project with proper
entity-level metrics and a written error analysis.

**Expert.** Reason about tokenization design (vocab size vs sequence length vs
multilingual fairness); know when classic models beat LLMs and prove it with a
benchmark; design task-appropriate eval (and know the limits of every metric);
handle multilinguality, code-switching, and domain shift. *Milestone:* you choose
the right rung of the ladder for a new problem and defend it with numbers.

## 7. Interview signals

What's probed: do you understand the machinery *under* the LLM, and can you
evaluate language tasks rigorously?

**Q: "Why does an LLM struggle to count the letters in a word?"**
Strong answer: it never sees letters — it sees *subword tokens*. "strawberry"
might be 2–3 tokens, so character-level operations are invisible to it unless the
pattern was memorized. Ties to BPE/tokenization, and you'd mention this affects
spelling, reversal, and arithmetic-on-digits tasks.

**Q: "BLEU vs ROUGE — when and why?"**
Strong answer: BLEU is *precision-oriented* n-gram overlap with a brevity penalty
— built for machine translation. ROUGE is *recall-oriented* (did the summary
cover the reference?) — built for summarization. Both measure surface overlap,
not meaning, so a correct paraphrase can score low; for semantic tasks add
BERTScore or an LLM judge. Always use `sacrebleu` for reproducibility.

**Q: "Build a spam classifier — would you use an LLM?"**
Strong answer: probably not first. A TF-IDF + LogReg/SVM baseline is faster,
cheaper, interpretable, and often competitive; train it, measure F1, and only
escalate to a transformer/LLM if the baseline underperforms the target. Shows
cost-aware judgment.

**Q: "Explain how subword tokenization is trained."**
Strong answer: BPE starts from characters and greedily merges the most frequent
adjacent pair, repeating to a target vocab size; WordPiece merges by likelihood
gain; Unigram starts large and prunes by a language-model objective
(SentencePiece). All guarantee no OOV. Bonus: discuss vocab-size/sequence-length
tradeoffs.
