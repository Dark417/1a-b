## 1. What it is

The conceptual and mathematical bedrock under every model you will ever call:
the linear-algebra/probability intuition, the mechanics of **gradient descent**,
the **bias–variance** picture, regularization, and the deep-learning toolbox —
CNNs, RNNs, attention, embeddings, loss functions, optimizers, normalization.

It exists because **a model is not a black box you should fear**. If you
understand *why* a network overfits, *why* a learning rate matters, *why* an
embedding captures similarity, and *what* a softmax actually does, you can debug
quality, pick the right approach, and reason about tradeoffs instead of guessing.
Even "prompt-only" applied roles hit a wall without this: tokenization quirks,
context-length effects, hallucination patterns, and eval design all trace back
to foundations.

## 2. Why employers want it

R1 puts *deep learning* as a named skill in ~28% of postings and **implies** it
nearly everywhere else. The signal employers read:

- **You reason about models, not vibes.** "Loss isn't going down" → you check
  learning rate, data leakage, label noise, initialization, gradient scale — a
  systematic differential diagnosis, not a shrug.
- **You pick the right tool.** Not every problem needs a 70B LLM; sometimes a
  logistic regression or a small fine-tune wins. Knowing *when* is senior
  judgment (see [`31.classic-ml-data-science.md`](31.classic-ml-data-science.md)).
- **You can read the field.** Papers assume this vocabulary; without it the
  monthly firehose of new methods is opaque.

## 3. Mental model

**Learning = minimizing a loss by following its gradient.** Everything else is
detail on top of that one idea.

A neural net is a parameterized function $f_\theta(x)$ composed of layers. You
define a **loss** $L(\theta)$ measuring how wrong it is, then nudge $\theta$
downhill:

$$
\theta_{t+1} = \theta_t - \eta \, \nabla_\theta L(\theta_t)
$$

where $\eta$ is the **learning rate** and $\nabla_\theta L$ is computed by
**backpropagation** — the chain rule applied layer by layer, right to left.

The **bias–variance** decomposition of expected error:

$$
\mathbb{E}[(y-\hat f)^2] = \underbrace{(\text{Bias})^2}_{\text{underfit}} + \underbrace{\text{Var}}_{\text{overfit}} + \underbrace{\sigma^2}_{\text{irreducible}}
$$

- **High bias / underfit** → model too simple; train *and* val loss both high.
  Fix: bigger model, more features, train longer.
- **High variance / overfit** → train loss low, val loss high. Fix: more data,
  regularization (L2/dropout), early stopping, simpler model.

The training-dynamics picture, in words:

```
data ──▶ forward pass ──▶ prediction ──▶ loss
  ▲                                         │
  │                                         ▼
params ◀── optimizer step ◀── gradients ◀── backprop
```

Cross-entropy for classification (the workhorse loss, also the LLM next-token
objective):

$$
L = -\sum_i y_i \log \hat y_i, \qquad \hat y = \mathrm{softmax}(z)
$$

## 4. The landscape

**The math you actually need.** Linear algebra (matrix multiply, dot products as
similarity, eigen/SVD intuition), probability (distributions, expectation,
Bayes, KL divergence), and calculus (gradients, the chain rule). Not proofs —
*intuition you can compute with*.

**Architectures (the toolbox).**

| Family | Built for | Key idea | Where it lives now |
|---|---|---|---|
| **MLP** | tabular / generic | stacked linear + nonlinearity | building block everywhere |
| **CNN** | grids (images) | local weight-sharing, translation invariance | vision, still strong |
| **RNN / LSTM / GRU** | sequences | hidden state carried across time | mostly replaced by attention |
| **Attention / Transformer** | sequences, sets | every token attends to every token | LLMs, vision, audio — dominant |
| **Embeddings** | discrete → vector | learned dense lookup; similarity = geometry | tokens, users, items, retrieval |
| **Autoencoders / VAEs** | representation, generation | compress then reconstruct | anomaly detection, diffusion priors |

**Optimizers.** SGD (+momentum) → **Adam/AdamW** (adaptive per-parameter rates;
AdamW decouples weight decay and is the LLM default) → Lion, Adafactor (memory-
lean), Muon (recent). Learning-rate **schedules** (warmup → cosine decay) matter
as much as the optimizer.

**Regularization.** L2/weight decay, dropout, early stopping, data augmentation,
label smoothing, batch/layer normalization (also stabilizes training), and the
biggest one of all: **more and cleaner data**.

**Normalization.** BatchNorm (vision), **LayerNorm/RMSNorm** (transformers).
RMSNorm drops the mean-centering for speed and is now standard in LLMs.

**Activations.** ReLU → GELU/SiLU → **SwiGLU** (gated, used in Llama/Mistral
FFNs). Nonlinearity is what lets stacked layers express more than one big linear
map.

**Failure modes to recognize on sight.** Vanishing/exploding gradients (→ resid-
ual connections, normalization, gradient clipping), dead ReLUs, exploding loss
(LR too high), loss not moving (LR too low / bug / data leak), train-val gap
(overfit), data leakage (val info bleeding into train — silently inflates scores).

## 5. Worked example

A from-scratch **two-layer MLP in NumPy** with manual backprop on a toy task —
the clearest way to internalize forward pass + gradients + the update rule. Then
the idiomatic PyTorch equivalent.

```python
"""mlp_from_scratch.py — backprop by hand, then PyTorch. Runs on CPU, exit 0."""
import numpy as np

rng = np.random.default_rng(0)

# Toy: learn XOR (not linearly separable -> needs a hidden layer).
X = np.array([[0, 0], [0, 1], [1, 0], [1, 1]], dtype=np.float64)
y = np.array([[0.0], [1.0], [1.0], [0.0]])  # XOR targets

def sigmoid(z): return 1.0 / (1.0 + np.exp(-z))

# Params: 2 -> 4 -> 1
W1 = rng.normal(0, 1, (2, 4)); b1 = np.zeros((1, 4))
W2 = rng.normal(0, 1, (4, 1)); b2 = np.zeros((1, 1))
lr = 0.5

for step in range(5000):
    # ---- forward ----
    h_pre = X @ W1 + b1            # (4,4)
    h = sigmoid(h_pre)
    o_pre = h @ W2 + b2           # (4,1)
    o = sigmoid(o_pre)
    loss = np.mean((o - y) ** 2)  # MSE

    # ---- backward (chain rule) ----
    dL_do = 2 * (o - y) / len(X)              # dLoss/dOutput
    do = dL_do * o * (1 - o)                  # through sigmoid
    dW2 = h.T @ do;            db2 = do.sum(0, keepdims=True)
    dh = (do @ W2.T) * h * (1 - h)            # backprop to hidden
    dW1 = X.T @ dh;            db1 = dh.sum(0, keepdims=True)

    # ---- SGD update ----
    W2 -= lr * dW2; b2 -= lr * db2
    W1 -= lr * dW1; b1 -= lr * db1

    if step % 1000 == 0:
        print(f"step {step:4d}  loss {loss:.4f}")

print("predictions:", sigmoid(sigmoid(X @ W1 + b1) @ W2 + b2).round(2).ravel())
```

The same model in **PyTorch** — autograd handles the backward pass:

```python
import torch, torch.nn as nn
torch.manual_seed(0); torch.set_num_threads(1)  # CPU-fast, deterministic

X = torch.tensor([[0,0],[0,1],[1,0],[1,1]], dtype=torch.float32)
y = torch.tensor([[0.],[1.],[1.],[0.]])

model = nn.Sequential(nn.Linear(2, 4), nn.Sigmoid(), nn.Linear(4, 1), nn.Sigmoid())
opt = torch.optim.Adam(model.parameters(), lr=0.05)
loss_fn = nn.MSELoss()

for step in range(2000):
    opt.zero_grad()
    loss = loss_fn(model(X), y)
    loss.backward()          # autograd computes every gradient
    opt.step()

print(model(X).detach().round().ravel())  # -> tensor([0., 1., 1., 0.])
```

The point: PyTorch's `loss.backward()` is *exactly* the chain-rule bookkeeping
you wrote by hand above — automated and GPU-accelerated.

## 6. How to learn it

**Beginner (0–3 months).** Linear algebra + probability intuition (3Blue1Brown,
*Essence of Linear Algebra*); Andrew Ng's ML course; implement linear/logistic
regression and a tiny MLP from scratch in NumPy. *Milestone:* hand-derive and
code backprop for a 2-layer net (the example above).

**Intermediate / job-ready (3–9 months).** Work through *Deep Learning*
(Goodfellow) or fast.ai; train CNNs and RNNs in PyTorch on real datasets;
internalize over/underfitting by inducing and fixing each; understand attention
from the inside. *Milestone:* you can diagnose a stuck training run by symptom.

**Expert (9+ months).** Read foundational papers (ResNet, BatchNorm, Adam,
Attention Is All You Need); understand optimization landscapes, initialization,
and scaling; reproduce a paper's result. *Milestone:* you can propose and
justify an architecture/loss choice from first principles for a new problem.

## 7. Interview signals

- **"Explain the bias–variance tradeoff."** Strong answer uses the train/val gap
  to *diagnose* and names concrete fixes for each side — not just the textbook
  equation.
- **"Your training loss is flat. What do you check?"** LR (too low/high), a bug
  in the loss/labels, data leakage, bad init, exploding/vanishing gradients,
  dead units — a *systematic* list, ideally ordered by likelihood.
- **"Why does Adam often beat plain SGD?"** Per-parameter adaptive learning rates
  from running estimates of gradient mean/variance; faster convergence on sparse/
  noisy gradients; AdamW fixes weight-decay coupling. Bonus: when SGD+momentum
  still generalizes better.
- **"What is overfitting and how do you fight it?"** Memorizing train noise →
  poor generalization; fixes ranked: more/cleaner data, regularization, early
  stopping, simpler model, augmentation.
- **Derive backprop for one layer.** They want to see you apply the chain rule
  calmly and know what a gradient *is*.
