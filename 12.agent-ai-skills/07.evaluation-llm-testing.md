# 07 · Evaluation & LLM Testing

> Skill #07 (Tier 1 — Core). *Eval suites, LLM-as-judge, RAG/agent metrics,
> regression gating.* ~65% and rising; now its own role at Scale and a named
> requirement at Anthropic. See the rationale in
> [`../11.agent-ai-engineer/03.ranked-skills.md`](../11.agent-ai-engineer/03.ranked-skills.md).

---

## 1. What it is

The discipline of **measuring non-deterministic systems**: building eval suites
for LLM apps. Covers task metrics, **LLM-as-judge**, RAG metrics (faithfulness,
context precision/recall), agent-trajectory evaluation, human eval, and
**regression/CI gating** so quality is enforced, not hoped for.

It exists because **you can't ship or improve what you can't measure** — and LLM
quality is slippery (same input, different output; no single "correct" answer).
Disciplined evaluation is the line between a flashy demo and a product you can
trust in production.

## 2. Why employers want it

Evaluation has become its own role (Scale `S16`) and an explicit requirement at
labs (Anthropic `S3`, `S5`). The signal:

- **You make iteration safe.** A prompt/model/RAG change is gated by an eval that
  catches regressions before users do.
- **You can defend quality claims.** "It's better" backed by numbers on a
  held-out set, not anecdotes.
- **You design evals for fuzzy tasks** — where there's no exact-match answer —
  using rubrics, judges, and the right metric for the job.

## 3. Mental model

An eval is a **dataset + a metric + a runner**, run as a regression gate.

```
dataset (inputs [+ refs/rubric]) ─► system under test ─► outputs
                                                            │
                          metric (exact / similarity / judge / RAG / trajectory)
                                                            │
                                  aggregate score ─► compare to baseline ─► PASS/FAIL gate
```

**Pick the metric to the task:**

- **Deterministic** (classification, extraction, code that runs): exact match,
  F1, pass@k, unit tests. Cheap, objective — use whenever the task allows it.
- **Reference-based** (translation, summary with a gold answer): BLEU/ROUGE,
  BERTScore, semantic similarity. Noisy; use as a signal, not a verdict.
- **Reference-free / open-ended** (chat quality, helpfulness, tone): **LLM-as-
  judge** — a strong model scores the output against a rubric (pointwise or
  pairwise). Calibrate the judge against human labels; beware position/verbosity
  bias.
- **RAG-specific**: **faithfulness** (answer supported by context),
  **context precision/recall** (did retrieval get the right chunks), answer
  relevancy.
- **Agent-specific**: trajectory/process evals — did it call the right tools in a
  sensible order, recover from errors, stay in budget — plus final-outcome
  success.

**Levels of evaluation**: unit (one prompt/component) → integration (the full
pipeline) → online (production A/B, user feedback, win-rate). Offline evals gate
merges; online evals catch what offline missed.

## 4. The landscape

**Frameworks/tools.**

| Tool | Focus |
|---|---|
| **Ragas** | RAG metrics (faithfulness, context precision/recall, relevancy) |
| **DeepEval** | pytest-style LLM unit tests, many metrics, CI-friendly |
| **promptfoo** | prompt/model A/B + regression, config-driven |
| **OpenAI Evals / Inspect (AISI)** | general eval harnesses |
| **LangSmith / Langfuse / Phoenix** | tracing + eval datasets + judges |
| **TruLens / Braintrust** | eval + observability for LLM apps |

**LLM-as-judge techniques.** Pointwise (score 1–5 on a rubric), pairwise (A vs B,
compute win-rate), reference-guided (judge with a gold answer), and
**G-Eval**-style chain-of-thought scoring. Mitigate biases: randomize position,
control for length, use multiple judges or a strong judge model, and **validate
the judge against human agreement**.

**Benchmarks (know them, don't over-trust them).** MMLU, GSM8K/MATH, HumanEval/
MBPP (code), HELM, MT-Bench/Chatbot Arena (preference), BIG-bench. Public
benchmarks are contaminated and rarely match *your* task — build a **task-
specific** eval set.

**Process & data.** Curate a representative, versioned eval set (include edge
cases and past failures); split dev/test; track metric history; set a regression
threshold; gate in CI. Add **human eval** for a sampled slice and to calibrate
judges.

## 5. Worked example

A small **LLM-as-judge** eval that scores answers against a rubric and gates on a
threshold — the pattern you'd wire into CI. Uses the Anthropic SDK with a
structured-output judge for reliable scoring (`claude-opus-4-8`).

```python
"""eval_judge.py — LLM-as-judge eval with a CI-style gate. Anthropic SDK."""
import json
from anthropic import Anthropic

client = Anthropic()

# 1. A versioned eval set: input, the system's answer, and a grading rubric.
CASES = [
    {"q": "What is the refund window?",
     "answer": "You have 30 days to return a purchase.",
     "rubric": "Correct iff it states a 30-day window."},
    {"q": "What is the refund window?",
     "answer": "Refunds are not allowed.",
     "rubric": "Correct iff it states a 30-day window."},
]

JUDGE_SCHEMA = {
    "type": "object",
    "properties": {
        "passed": {"type": "boolean"},
        "reason": {"type": "string"},
    },
    "required": ["passed", "reason"],
    "additionalProperties": False,
}

def judge(q: str, answer: str, rubric: str) -> dict:
    resp = client.messages.create(
        model="claude-opus-4-8",
        max_tokens=256,
        output_config={"format": {"type": "json_schema", "schema": JUDGE_SCHEMA}},
        system="You are a strict grader. Apply the rubric exactly and explain briefly.",
        messages=[{"role": "user", "content":
            f"Question: {q}\nAnswer: {answer}\nRubric: {rubric}\nGrade it."}],
    )
    return json.loads(next(b.text for b in resp.content if b.type == "text"))

results = [judge(c["q"], c["answer"], c["rubric"]) for c in CASES]
pass_rate = sum(r["passed"] for r in results) / len(results)

THRESHOLD = 0.9
print(f"pass_rate={pass_rate:.2f} (threshold {THRESHOLD})")
for c, r in zip(CASES, results):
    print(f"  {'PASS' if r['passed'] else 'FAIL'}: {c['answer'][:40]!r} -- {r['reason']}")

# CI gate: nonzero exit fails the build on regression.
import sys
sys.exit(0 if pass_rate >= THRESHOLD else 1)
```

Why this is the right shape: the judge returns a **structured** verdict (no
fragile parsing), the eval set is explicit and versionable, and the script
**exits nonzero on regression** so it gates a merge. For RAG you'd swap the judge
for Ragas faithfulness/context-recall; for agents you'd score the tool
trajectory. Always sanity-check the judge against a few human labels first.

## 6. How to learn it

**Beginner (0–3 months).** Build a 20-example eval set for one task; use
exact-match/F1 where possible; write a pytest that fails on regression.
*Milestone:* a CI eval that blocks a prompt change that drops accuracy.

**Intermediate / job-ready (3–9 months).** Add LLM-as-judge (validated against
human labels); use Ragas/DeepEval for a RAG app; build pairwise win-rate evals;
track metric history. *Milestone:* an eval dashboard gating a real app, with a
calibrated judge.

**Expert (9+ months).** Design trajectory evals for agents; build red-team/
adversarial eval sets; run online A/B with statistical rigor; manage eval data
quality and contamination. *Milestone:* you own the eval system that quality
decisions for a product flow through.

## 7. Interview signals

- **"How do you evaluate a system with no single correct answer?"** Rubric-based
  LLM-as-judge (validated against humans), pairwise win-rate, and task-specific
  reference-free metrics — plus why public benchmarks don't substitute.
- **"How do you evaluate a RAG system?"** Faithfulness + context precision/recall
  + answer relevancy (Ragas), separating *retrieval* quality from *generation*
  quality so you know which to fix.
- **"How do you keep an LLM-as-judge honest?"** Calibrate against human labels,
  randomize position, control for length, use a strong/multi judge, and report
  judge–human agreement.
- **"How do you stop quality regressions?"** Versioned eval set + metric +
  threshold gated in CI; alert on online metric drift; include past failures as
  regression cases.
- **"What's wrong with benchmark scores?"** Contamination, distribution
  mismatch with your task, and gaming — build your own task eval set.
