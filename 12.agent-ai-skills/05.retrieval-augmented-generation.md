# 05 · Retrieval-Augmented Generation (RAG)

> Skill #05 (Tier 1 — Core). *Chunking, embeddings, retrieval, reranking,
> grounded context assembly.* The most-requested production *application pattern*
> (~75% of sources). See the rationale in
> [`../11.agent-ai-engineer/03.ranked-skills.md`](../11.agent-ai-engineer/03.ranked-skills.md).

---

## 1. What it is

**RAG** grounds an LLM in external knowledge at query time: instead of relying on
the model's frozen weights, you **retrieve** relevant passages from your own
corpus and put them in the prompt so the model answers *from* them, with
citations. End to end it covers chunking, embeddings, indexing, retrieval
(dense/sparse/hybrid), reranking, context assembly, and the failure modes.

It exists because it's **the default way enterprises get value from LLMs without
retraining**: connect a model to proprietary docs, tickets, code, or policies and
get grounded, up-to-date, attributable answers. Cheaper than fine-tuning, updates
instantly (re-index, don't retrain), and reduces hallucination.

## 2. Why employers want it

It's the single most likely skill to land an applied AI job (S2–S26 across the
corpus). The signal:

- **You can ship the canonical enterprise use case** — "chat with our docs",
  support copilots, internal search — reliably.
- **You understand the failure modes.** Bad chunking, stale index, lost-in-the-
  middle, retrieval misses — and how to diagnose and fix each.
- **You ground and cite.** You turn a hallucination-prone chatbot into a system
  that answers from sources users can verify.

## 3. Mental model

RAG is two phases: an **offline indexing** pipeline and an **online query**
pipeline.

```
INDEX (offline):  docs ─► clean ─► chunk ─► embed ─► vector store (+ keyword index)

QUERY (online):   question ─► embed ─► ANN search ─┐
                                     keyword search ─┼─► fuse ─► rerank ─► top-k
                                                                              │
              prompt = system + [retrieved chunks w/ citations] + question ◄──┘
                                          │
                                          ▼
                                   LLM ─► grounded, cited answer
```

The core idea: **similarity is geometry.** An embedding model maps text to a
vector so that semantically related text lands nearby; retrieval is a
nearest-neighbor search in that space.

Knobs that decide quality, roughly in order of impact:

1. **Chunking** — size, overlap, and boundaries (semantic > fixed-size). Too big
   = diluted relevance and wasted context; too small = lost context.
2. **Embedding model** — domain fit and dimensionality.
3. **Retrieval mode** — dense (semantic), sparse/BM25 (lexical, exact terms), or
   **hybrid** (both, fused). Hybrid usually wins.
4. **Reranking** — a cross-encoder re-scores the top candidates; big precision
   lift for a little latency.
5. **Context assembly** — how many chunks, in what order, with citations.
   Mitigate **lost-in-the-middle** (models attend to the head/tail more than the
   middle) by putting the best chunks at the edges.

## 4. The landscape

**Chunking** — fixed-size+overlap (simple baseline) → recursive/structure-aware
(split on headings/sentences) → **semantic chunking** (group by embedding
similarity) → late chunking / parent-document (embed small, return large) →
proposition/atomic. Match the chunk to the *retrieval unit* you want.

**Embeddings** — open: sentence-transformers, **BGE**, E5, GTE, Nomic; hosted:
OpenAI `text-embedding-3`, Cohere, Voyage. Pick by MTEB benchmark + domain +
dimension/cost. (Deeper dive: skill [`09.vector-databases-embeddings.md`](09.vector-databases-embeddings.md).)

**Retrieval** — dense (ANN over embeddings) · sparse (**BM25**, SPLADE) · **hybrid**
(reciprocal-rank fusion of both). Add **metadata filtering** (date, source, ACL)
to scope results.

**Reranking** — cross-encoder rerankers (Cohere Rerank, BGE-reranker,
`mixedbread`/`jina` rerankers). Retrieve ~20–50 cheap candidates, rerank to the
top 3–8.

**Vector stores** — FAISS (in-proc), Chroma (local), **Qdrant / Milvus /
Weaviate** (servers), **pgvector** (Postgres), Pinecone (managed). See [`09`](09.vector-databases-embeddings.md).

**Orchestration frameworks** — LlamaIndex (RAG-first), LangChain, Haystack, DSPy.
Use them for plumbing; understand the pieces so you can debug.

**Advanced patterns** — query rewriting/expansion, HyDE (hypothetical doc
embeddings), multi-query, RAG-fusion, contextual retrieval (prepend doc context
to chunks before embedding), **graph RAG** (entity/relationship graphs),
agentic/iterative retrieval (the agent decides what to fetch next), and
long-context "stuffing" as a baseline to compare against.

**Failure modes to name on sight** — bad chunking, **stale index** (corpus
changed, embeddings didn't), embedding/domain mismatch, retrieval miss (answer
isn't in top-k), **lost-in-the-middle**, context overflow, and the model ignoring
context (prompt doesn't force grounding/citation).

## 5. Worked example

A minimal but correct RAG pipeline with **local** open models (runs offline) and
hybrid-ish retrieval: embed with sentence-transformers, search with FAISS, then
assemble a grounded, citation-forcing prompt.

```python
"""mini_rag.py — local RAG: embed -> FAISS -> grounded prompt. CPU-friendly."""
import numpy as np
from sentence_transformers import SentenceTransformer
import faiss

# 1. Corpus -> chunks (here each doc is one chunk for brevity).
docs = [
    "Acme's refund policy allows returns within 30 days of purchase.",
    "Enterprise plans include a dedicated support engineer and 99.9% SLA.",
    "The API rate limit is 1000 requests per minute on the Pro plan.",
    "Data is encrypted at rest with AES-256 and in transit with TLS 1.3.",
]

# 2. Embed the corpus once (offline indexing).
model = SentenceTransformer("BAAI/bge-small-en-v1.5")
emb = model.encode(docs, normalize_embeddings=True)   # cosine == inner product
index = faiss.IndexFlatIP(emb.shape[1])               # exact search (use HNSW at scale)
index.add(np.asarray(emb, dtype="float32"))

def retrieve(query: str, k: int = 2):
    q = model.encode([query], normalize_embeddings=True).astype("float32")
    scores, idx = index.search(q, k)
    return [(docs[i], float(s)) for i, s in zip(idx[0], scores[0])]

# 3. Online query: retrieve, then build a grounded, citation-forcing prompt.
question = "How long do I have to return something?"
hits = retrieve(question, k=2)

context = "\n".join(f"[{i+1}] {text}" for i, (text, _) in enumerate(hits))
prompt = (
    "Answer ONLY from the context. Cite sources as [n]. "
    "If the answer isn't in the context, say you don't know.\n\n"
    f"Context:\n{context}\n\nQuestion: {question}"
)
print("Retrieved:", [round(s, 3) for _, s in hits])
print(prompt)
# Feed `prompt` to your LLM (skill #04). Expected grounded answer:
#   "You have 30 days to return a purchase. [1]"
```

To make this production-grade you'd add: real chunking with overlap, a BM25
index fused with the dense scores, a cross-encoder reranker over the top ~20, an
ANN index (HNSW), metadata filters for access control, and an eval set measuring
**faithfulness** and **context recall** (skill #07).

## 6. How to learn it

**Beginner (0–3 months).** Build the pipeline above; swap FAISS for Chroma; try a
hosted embedding model; measure recall by hand on 20 questions. *Milestone:* a
"chat with a folder of PDFs" app that cites sources.

**Intermediate / job-ready (3–9 months).** Add hybrid retrieval + reranking;
experiment with chunking strategies and measure the difference; instrument an
eval set (Ragas/DeepEval) for faithfulness/context-precision/recall; handle
metadata filtering and ACLs. *Milestone:* a RAG service with hybrid+rerank and a
quality dashboard, beating a naive baseline on your evals.

**Expert (9+ months).** Contextual/graph/agentic retrieval; query rewriting;
index freshness pipelines; multi-tenant isolation; cost/latency tuning; choose
RAG vs long-context vs fine-tune per problem. *Milestone:* you own a production
RAG system with monitored quality, fresh indexes, and a clear evaluation loop.

## 7. Interview signals

- **"Design a RAG system for our support docs."** Strong answer covers the full
  pipeline, names the knobs (chunking, hybrid, rerank, citations), and — crucially
  — **how you'd evaluate it** (faithfulness, context recall, answer relevancy).
- **"The model is hallucinating despite RAG. Why?"** Retrieval miss (answer not
  in top-k), bad chunking, prompt not forcing grounding, lost-in-the-middle, or
  stale index — and how to isolate which.
- **"Dense vs sparse vs hybrid?"** Dense = semantic/paraphrase; sparse/BM25 =
  exact terms, names, codes; hybrid fuses both and usually wins. Reranking adds
  precision on top.
- **"When is RAG the wrong choice?"** When the knowledge is small enough to fit
  in context, when behavior (not knowledge) needs to change (→ fine-tune), or
  when freshness/latency demands a different design.
- **"How do you keep the index fresh?"** Incremental re-embedding on doc change,
  versioned indexes, deletion/upsert, and monitoring for drift.
