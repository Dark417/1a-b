## 1. What it is

**Observability** is the ability to understand what an LLM system is doing in
production from the data it emits — traces, metrics, and logs — *without* shipping
new code to investigate. **Monitoring** is the continuous watch on top: dashboards,
SLOs, and alerts on cost, latency, errors, and **quality drift**.

It exists because LLM systems fail *silently and expensively* in ways traditional
software doesn't. A normal service is broken when it 500s; an LLM service can
return a perfectly-formatted, confident, *wrong* answer — HTTP 200, zero
exceptions, total failure. Meanwhile token spend can 10× overnight from a prompt
change, latency creeps as context grows, and quality drifts as the model provider
silently updates the endpoint or your data distribution shifts. You cannot see any
of this without purpose-built observability for **non-deterministic, probabilistic,
multi-step** systems.

## 2. Why employers want it

Section 11 ranks this #22 and notes it is now **its own role at Anthropic (S5)**.
The hiring signal:

- **You keep production honest.** You catch regressions, runaway cost, and latency
  creep *before* users (or finance) do.
- **You can trace a multi-step agent.** When a 7-step agent gives a bad answer,
  you can pinpoint *which* tool call or retrieval went wrong — the single most
  valuable debugging skill in agentic systems.
- **You make quality measurable in prod.** Online evals, user feedback, and drift
  detection turn "it feels worse" into a number with an alert.
- **You control spend.** Per-feature/per-user token & cost dashboards are how a
  company avoids a surprise five-figure bill.

It's the production counterpart to evaluation (#07): evals gate *before* ship,
observability watches *after* — together they close the quality loop.

## 3. Mental model

**The three pillars, adapted for LLMs:**

```
  TRACES  — the spine. One TRACE = one request; nested SPANS = each step.
            Agent run
            ├─ span: retrieve(query)        → 8 chunks, 40ms
            ├─ span: llm.call(plan)          → 1.2k tok in / 200 out, 900ms, $0.004
            ├─ span: tool.web_search(...)    → 3 results, 600ms
            └─ span: llm.call(final answer)  → 4k tok in / 500 out, 2.1s, $0.02
            (capture: prompt, response, model, tokens, cost, latency, error, metadata)

  METRICS — aggregates over traces: p50/p95/p99 latency, tokens/req, $/req,
            error rate, requests/min, cache-hit rate, thumbs-up rate.

  LOGS / EVENTS — raw prompt/response payloads + user feedback (👍/👎), tied to a trace.
```

**Concepts to own:**

- **A trace is the unit of debugging.** Without nested spans, an agent is a black
  box. *With* them, you replay the exact prompt/response at each step and see
  where it went wrong. This is why OpenTelemetry-style tracing is the foundation.
- **Token & cost accounting.** Every span records input/output tokens and a cost
  derived from the model's price. Aggregate by feature, user, model, and prompt
  version to find waste (e.g., a RAG step stuffing 30k tokens of context).
- **SLOs/SLIs for LLMs.** Define service-level *indicators* (p95 latency, error
  rate, *and* quality proxies like groundedness or thumbs-up rate) and *objectives*
  (targets), then alert on burn.
- **Drift — three kinds.** *Data drift* (input distribution shifts), *quality/
  concept drift* (answers get worse for the same inputs — often a silent provider
  model update), *embedding drift* (RAG retrieval degrades). Detect via online
  evals, statistical tests, and user-feedback trends.
- **Online evaluation.** Run an LLM-as-judge or rules on a *sample* of live
  traffic to score quality continuously (no ground truth needed) and alert on
  regression. Bridges to #07.
- **Sampling & PII.** You can't store everything at scale — sample traces, and
  scrub PII before logging prompts/responses (ties to #19).

## 4. The landscape

**LLM-native observability platforms**
- **Langfuse** — open-source, self-hostable; tracing, prompt management,
  evals, cost/token dashboards, datasets. Strong default for portability.
- **LangSmith** (LangChain) — tracing, datasets, online evals, prompt hub; deepest
  if you're on LangChain/LangGraph but works standalone.
- **Arize Phoenix** — OSS tracing + evals built on OpenTelemetry/OpenInference;
  great for RAG/embedding drift analysis. (Arize AX = the hosted enterprise tier.)
- **Helicone** — proxy-based: drop-in base-URL swap captures cost/latency/caching
  with near-zero code. Easiest to adopt.
- **OpenLLMetry** (Traceloop) / **OpenInference** — *standards*: OpenTelemetry
  semantic conventions for LLMs so traces are vendor-portable.
- Others: **Weights & Biases Weave**, **Braintrust**, **Datadog LLM Observability**,
  **PromptLayer**, **Lunary**, **HoneyHive**.

**General observability you still need underneath**
- **OpenTelemetry** (the tracing standard), **Prometheus + Grafana** (metrics/
  dashboards), **Loki/ELK** (logs), **Jaeger/Tempo** (trace backends),
  **Sentry** (errors), **DCGM exporter** (GPU metrics for self-hosted serving).

**What to instrument (the checklist):** per call — model, prompt version, input/
output tokens, cost, latency, finish reason, error; per trace — full step tree,
retrieved context, tool calls/results; per user — feedback, session; per system —
cache-hit rate, queue depth, rate-limit hits.

**Tradeoffs:** *proxy-based* (Helicone) = trivial setup but shallow (no app
context, no nested spans); *SDK/OTel-based* (Langfuse/LangSmith/Phoenix) = richer
traces and evals but you instrument code. Open-source + OTel (Langfuse/Phoenix)
buys portability and self-hosting (data residency); hosted SaaS buys less ops.
Always sample at high volume; always scrub PII.

## 5. Worked example

Minimal, vendor-neutral **tracing + cost/latency capture** for an agent step,
plus an online-eval gate — the shape every platform formalizes. Runs on CPU; the
"LLM" is a stub so you see the instrumentation, not the model.

```python
"""llm_observability.py — trace spans, token/cost/latency, online-eval alert.
Run: python llm_observability.py
"""
import time, uuid, json
from contextlib import contextmanager
from dataclasses import dataclass, field, asdict

# Price table ($/1K tokens) — the basis of every cost dashboard.
PRICES = {"haiku": (0.0008, 0.004), "sonnet": (0.003, 0.015)}  # (input, output)


def cost(model: str, in_tok: int, out_tok: int) -> float:
    pin, pout = PRICES[model]
    return (in_tok / 1000) * pin + (out_tok / 1000) * pout


@dataclass
class Span:
    name: str
    start: float
    model: str = ""
    in_tok: int = 0
    out_tok: int = 0
    latency_ms: float = 0.0
    usd: float = 0.0
    error: str | None = None


@dataclass
class Trace:
    trace_id: str = field(default_factory=lambda: uuid.uuid4().hex[:8])
    spans: list[Span] = field(default_factory=list)

    @contextmanager
    def span(self, name: str):
        s = Span(name=name, start=time.perf_counter())
        try:
            yield s
        except Exception as e:           # capture errors into the trace
            s.error = repr(e)
            raise
        finally:
            s.latency_ms = (time.perf_counter() - s.start) * 1000
            if s.model:
                s.usd = cost(s.model, s.in_tok, s.out_tok)
            self.spans.append(s)

    @property
    def total_usd(self) -> float:
        return sum(s.usd for s in self.spans)


def fake_llm(prompt: str, model: str):
    time.sleep(0.01)
    return {"text": "Paris is the capital of France.",
            "in_tok": len(prompt.split()), "out_tok": 7, "model": model}


# --- an instrumented agent step ---
def answer(question: str, tr: Trace) -> str:
    with tr.span("retrieve") as s:        # span 1: retrieval
        time.sleep(0.005)
        s.in_tok = 0
    with tr.span("llm.answer") as s:       # span 2: the model call
        out = fake_llm(question, model="haiku")
        s.model, s.in_tok, s.out_tok = out["model"], out["in_tok"], out["out_tok"]
        return out["text"]


# --- online eval: sample live traffic, score, alert on regression ---
def online_eval(answer_text: str, must_contain: str) -> bool:
    return must_contain.lower() in answer_text.lower()


if __name__ == "__main__":
    tr = Trace()
    ans = answer("What is the capital of France?", tr)
    print(json.dumps([asdict(s) for s in tr.spans], indent=2, default=str))
    print(f"\ntrace {tr.trace_id}  total cost ${tr.total_usd:.5f}  "
          f"p_latency {max(s.latency_ms for s in tr.spans):.1f}ms")

    ok = online_eval(ans, must_contain="Paris")
    print("ONLINE EVAL:", "PASS" if ok else "ALERT: quality regression!")
```

Every production platform (Langfuse/LangSmith/Phoenix) is a richer version of
exactly this: nested spans with model/token/cost/latency/error per step, rolled
into dashboards and SLO alerts, plus an online-eval sample that fires when a
quality proxy drops. The skill is *capturing the right fields at every step* so a
bad answer is debuggable and a cost spike is attributable.

## 6. How to learn it

**Beginner (weeks).** Add tracing to one LLM app with Langfuse or Helicone (a
base-URL swap or a decorator). Build a dashboard of tokens, cost, and p95 latency.
*Milestone:* you can answer "what did this exact request cost and how long did it
take?" from a UI, not a guess.

**Job-ready (1–3 months).** Instrument a multi-step agent/RAG app with nested
spans (OpenTelemetry/OpenInference), capture retrieved context and tool calls, add
👍/👎 feedback, define SLOs (p95 latency, error rate, groundedness), and wire an
online LLM-as-judge eval on sampled traffic with an alert. Scrub PII before
logging. *Milestone:* you can replay any failed agent run step-by-step and you get
paged when quality or cost drifts.

**Expert.** Design drift detection (data/quality/embedding) with statistical
tests; build cost-attribution by feature/user/prompt-version and act on it
(caching, model routing, context pruning); run continuous online evals as a
quality SLO; own the production quality loop end-to-end and feed regressions back
into the offline eval suite (#07). *Milestone:* a quality-and-cost control plane
the org trusts to catch silent regressions automatically.

## 7. Interview signals

What's probed: can you see, debug, and control a live, non-deterministic system?

**Q: "Your agent gives a wrong answer in production. How do you debug it?"**
Strong answer: open the **trace**, walk the nested spans — check the retrieved
context, each tool call's input/output, and each LLM call's exact prompt/response
— to localize the failing step (bad retrieval? bad tool result? bad final
synthesis?). Without span-level tracing it's unanswerable; *with* it, it's a
five-minute fix. Mention capturing inputs/outputs per span as the enabling design.

**Q: "How do you detect quality drift when you have no ground truth?"**
Strong answer: online evaluation — run an LLM-as-judge or rule-based checks
(groundedness, format, refusal rate) on a *sample* of live traffic, track the
score over time, and alert on a drop. Combine with user-feedback trends and a
golden offline eval set re-run on a schedule to catch silent provider model
updates.

**Q: "Costs doubled overnight. Find out why."**
Strong answer: cost dashboards broken down by feature/model/prompt-version and
token type. Usually a prompt change inflated input tokens (bigger context/RAG
top-k), a model swap, a retry storm, or a cache that stopped hitting. The
instrumentation (tokens + cost per span, tagged by version) is what makes this a
lookup instead of a hunt.

**Q: "What SLOs would you set for an LLM service?"**
Strong answer: p95/p99 latency, error rate, *and* a quality SLI (online-eval
score or thumbs-up rate) — not just uptime, because an LLM can be "up" and wrong.
Add cost-per-request as a budget. Alert on error-budget burn.
